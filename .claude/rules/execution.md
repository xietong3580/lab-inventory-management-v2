# 执行规则

## 代码开发流程
1. **先分析本轮改动范围**，明确需要修改的文件和影响
2. **优先复用现有能力**：service、日志、台账、导出等
3. **调研先行**：遇到需要大量读文件/搜代码时，优先使用 subagent 做调研
4. **调研后实现**：调研结论返回主会话后，再开始实现
5. **完成自检**：每次修改完成后必须先自检，再回传结果

## 技术决策原则
- 先最小可行方案，再逐步增强
- 不做无意义重构
- 保持向后兼容：接入真实数据时，优先保证旧功能不被破坏
- 跨端兼容：桌面端与移动端都要可读可用

## 文件修改规范
- 明确每个文件的修改目的
- 保持代码风格一致
- 注释重要决策点
- 避免破坏现有功能
