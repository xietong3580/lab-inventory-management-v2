# Step 10-1A 真实旧系统样本 CSV 小批量迁移验收准备

> **编写日期**：2026-06-28
> **编写性质**：验收准备文档，不修改任何功能代码
> **前置条件**：产品 CSV 正式导入链路已完成阶段性闭环（Step 9-5E-final 已通过）

---

## 一、背景

当前产品 CSV 导入链路已完成阶段性闭环：

```
上传 CSV → 预览校验 → 二次确认 → 备份确认 → 正式写库 → 结果展示 → Products 可见 → AuditLog 可追溯
```

Step 9-5E 最终验收使用手工编写的测试 CSV（`库存导入测试.csv`，3 行），字段命名和格式与新系统一致，已全部通过。

但真正用于替换或并行旧系统之前，CSV 导入功能必须消化旧系统真实导出的产品数据。旧系统的字段命名、编码方式、数据格式、空值约定、库存口径可能与新系统存在差异，必须通过小批量迁移验收发现这些问题并确认导入链路可以正确处理。

**核心原则**：先验证 10~30 条样本，不追求一次性全量迁移。

---

## 二、本轮目标

1. **文档准备**（本轮）：梳理旧系统字段映射、验收流程、样本选择规则、可能遇到的问题与处理建议
2. **用户准备**（后续）：从旧系统导出 10~30 条真实产品数据的 CSV，按本文档执行小批量迁移验收
3. **验收通过后**（后续）：再考虑更大规模产品数据导入

本轮不修改任何功能代码，不执行真实写库操作。

## 三、验收前准备

### 3.1 安全准备

| # | 准备项 | 说明 |
|---|--------|------|
| 1 | 备份新系统数据库 | 在 设置 → 备份管理 下载最新备份文件 |
| 2 | 使用 CSV 副本 | 不直接操作旧系统原始导出文件，先复制一份 |
| 3 | 确认 admin 账号登录 | 当前角色必须是 admin（viewer 无导入权限） |
| 4 | 后端服务正常启动 | `python apps/api/main.py` 无报错 |
| 5 | 前端服务正常启动 | `npm run dev` → http://localhost:5173 可访问 |

### 3.2 样本数据准备

从旧系统导出产品 CSV，优先选择以下类型数据（建议每种 2~5 条）：

| 类型 | 目的 | 建议数量 |
|------|------|----------|
| 普通库存产品（库存 > 最低库存） | 验证正常导入流程 | 3~5 |
| 低库存产品（库存 ≤ 最低库存） | 验证低库存判定 | 2~3 |
| 库存为 0 的产品 | 验证零库存边界 | 2~3 |
| 有供应商字段的产品 | 验证 P1 可选字段 | 2~3 |
| 有品牌字段的产品 | 验证 P1 可选字段 | 2~3 |
| 有位置/库位字段的产品 | 验证 P1 可选字段 | 2~3 |
| 有异地库存字段的产品 | 验证 STOCK_CONTEXT 不写入 | 1~2 |
| 有虚拟库存字段的产品 | 验证 STOCK_CONTEXT 不写入 | 1~2 |
| 有总库存/总可售库存字段的产品 | 验证口径不合并 | 1~2 |
| 有备注字段的产品 | 验证 P2 字段 | 1~2 |

**建议样本总数**：10~30 行

## 四、建议样本选择规则

### 4.1 覆盖维度

| 维度 | 建议覆盖 | 验证点 |
|------|----------|--------|
| 库存状态 | 正常库存 / 低库存 / 零库存 | current_stock 写入正确，status 自动计算正确 |
| 分类多样性 | 至少 2~3 个不同分类 | 分类字段映射正确 |
| 单位多样性 | 瓶/盒/支/套/个等不同单位 | 单位字段映射正确 |
| 品牌 | 有品牌 / 无品牌 | 可选字段不存在时不报错 |
| 供应商 | 有供应商 / 无供应商 | 可选字段不存在时不报错 |
| 库位 | 有库位 / 无库位 | 可选字段不存在时不报错 |
| 备注 | 有备注 / 无备注 / 长备注 | P2 字段映射，长文本不截断 |
| SKU 格式 | 纯数字 / 纯字母 / 混合 / 短 SKU / 长 SKU | SKU 识别准确 |
| 产品名称 | 纯中文 / 含英文 / 含数字型号 / 含特殊字符（括号、斜杠等） | 名称不乱码，特殊字符不丢失 |
| 数字字段 | 整数 / 小数 / 负数 / 空值 | 数字校验行为符合预期 |

### 4.2 额外建议

- 如果旧系统导出的 CSV 有超过 20 列，建议先保留全量列，不要手工删减，以测试新系统对"多余字段"的容错能力
- 如果旧系统支持导出为 UTF-8 和 GBK 两种编码，建议两种都导出分别测试
- 如果旧系统导出 CSV 带有 BOM 头，标记出来，验收时观察是否有异常

## 六、迁移验收流程

### 6.1 验收流程总览

```
准备（备份 + 样本 CSV）
  → Step 1：打开导入预览页
  → Step 2：上传样本 CSV
  → Step 3：查看字段识别结果
  → Step 4：查看 errors / warnings
  → Step 5：核对库存口径提示
  → Step 6：判断可否导入（can_import）
  → Step 7：二次确认弹窗
  → Step 8：勾选已备份数据库
  → Step 9：执行正式导入
  → Step 10：查看导入结果
  → Step 11：到 Products 页面核对
  → Step 12：到 AuditLog 页面核对
  → Step 13：记录问题与建议
```

### 6.2 详细步骤

#### Step 1：打开产品导入预览页
- 以 admin 身份登录
- 导航到产品 CSV 导入预览页面
- 确认页面无报错，按钮可操作

#### Step 2：上传样本 CSV
- 选择从旧系统导出的样本 CSV（副本）
- 点击「开始预览」
- 等待预览结果返回

#### Step 3：查看字段识别
- 检查预览表格中每列的字段映射是否正确
- 特别关注：旧系统列名是否被正确识别为对应的新系统字段
- 如果旧系统列名与新系统不一致，看是否被识别为"参考列"或"未知列"

#### Step 4：查看 errors / warnings
- 检查是否有阻断 error（`can_import=false`）
- 检查 warnings 数量与类型
- 对于 error，记录具体行号和原因
- 对于 warning，判断是否与库存口径有关

#### Step 5：核对库存口径提示
- 确认 STOCK_CONTEXT 字段（异地库存/虚拟库存/总可售）前有「参考」标记
- 确认口径说明卡片中强调"仅导入本地真实库存"
- 确认低库存标签仅基于 current_stock ≤ min_stock

#### Step 6：判断可否导入
- `can_import=true`：可进入下一步
- `can_import=false`：检查 error 列表，修正 CSV 后重新预览
  - 常见原因：SKU 为空、产品名为空、current_stock 为非数字、CSV 内部重复 SKU

#### Step 7：二次确认弹窗
- 点击「执行正式导入」
- 二次确认弹窗应出现，显示 5 条确认事项
- 确认事项应包含导入数量、库存口径说明、SKU 跳过说明、备份提醒、不可撤销提醒

#### Step 8：勾选已备份数据库
- 勾选「我已确认上述信息，并已在导入前完成数据库备份」
- 未勾选时，「确认导入，写入数据库」按钮应禁用
- 勾选后按钮可点击

#### Step 9：执行正式导入
- 点击「确认导入，写入数据库」
- 弹窗关闭，开始导入
- 导入中显示 loading 状态和"正在正式导入，请勿关闭页面"文案

#### Step 10：查看导入结果
- 导入完成后查看结果卡片
- 核对：success、batch_id、total_rows、created_count、skipped_count、warning_count、error_count
- 查看 created_items 表格
- 查看 skipped_items 表格（如有）
- 查看 warnings 列表（如有）
- 查看上下文提示（成功/跳过/警告/失败）

#### Step 11：到 Products 页面核对
- 前往 /products 页面
- 搜索导入的新产品（按 SKU 或名称）
- 逐条核对：SKU、名称、分类、单位、current_stock、min_stock、位置、供应商、品牌
- 核对库存状态：正常 / 低库存 是否与预期一致
- 编辑一个产品，确认字段回填正确

#### Step 12：到 AuditLog 页面核对
- 前往审计日志页面
- 搜索操作类型「批量导入」
- 确认记录存在，操作人为当前 admin
- 确认产品列显示"批量导入 N 个产品"
- 确认摘要列显示 CSV 批量导入相关内容
- 确认不出现长英文 PRODUCTS_CSV_IMPORT 导致列重叠

#### Step 13：记录问题与建议
- 在本验收记录的「十二、验收记录表」中填写发现问题
- 标记每个问题的严重程度和后续处理建议

## 七、验收重点

### 必须逐项验证

| # | 验证项 | 重要性 | 验证方法 |
|---|--------|--------|----------|
| 1 | CSV 编码正常（UTF-8 / GBK） | 🔴 关键 | 上传后预览表格中文内容可读 |
| 2 | 中文字段/产品名称不乱码 | 🔴 关键 | 预览表格中产品名称中文正常 |
| 3 | SKU 准确、无丢失字符 | 🔴 关键 | 导入后 Products 页核对 SKU |
| 4 | current_stock 仅取本地真实库存 | 🔴 关键 | 导入后检查：remote_stock 等字段未合并到 current_stock |
| 5 | 异地库存不写入 current_stock | 🔴 关键 | 导入后库存 ≠ 异地库存 + 本地库存 |
| 6 | 虚拟库存不写入 current_stock | 🔴 关键 | 导入后库存 ≠ 虚拟库存 + 本地库存 |
| 7 | 总可售库存不写入 current_stock | 🔴 关键 | 导入后库存 ≠ 总可售库存 |
| 8 | 低库存状态正确 | 🟡 重要 | 低库存仅基于 current_stock ≤ min_stock |
| 9 | 重复 SKU skipped 不覆盖 | 🟡 重要 | 重复导入后原产品数据不变、skipped_count 正确 |
| 10 | 缺少 P0 字段阻断导入 | 🟡 重要 | 不含 SKU 等 P0 字段的 CSV → can_import=false |
| 11 | warning 不阻断导入 | 🟡 重要 | 有 warning 无 error → can_import=true，可正常导入 |
| 12 | DB 已存在 SKU 为 warning | 🟡 重要 | 再次导入同一 CSV → warning 而非 error |
| 13 | CSV 内部重复 SKU 为 error | 🟡 重要 | 同一 CSV 内有重复 SKU → error 阻断 |
| 14 | AuditLog 记录正确 | 🟢 常规 | 操作日志有 PRODUCTS_CSV_IMPORT，显示"批量导入" |
| 15 | Products 页可查看和编辑 | 🟢 常规 | 新增产品可查看详情、可编辑、字段回填正确 |
| 16 | 事务完整性 | 🔴 关键 | 导入失败时不会残留半批数据 |

## 八、可能出现的问题与处理建议

| # | 可能问题 | 原因分析 | 严重程度 | 处理建议 |
|---|----------|----------|----------|----------|
| 1 | 中文产品名称乱码 | CSV 不是 UTF-8 编码（如 GBK） | 🔴 阻断 | 用记事本/VSCode 将 CSV 另存为 UTF-8 编码 |
| 2 | 字段名不匹配（如"产品编号"而非 SKU） | 旧系统列名与新系统不一致 | 🔴 可能阻断 | 将 CSV 列名改为新系统字段名；后续可考虑增加字段别名映射 |
| 3 | SKU 为空 | 旧系统某些产品无 SKU | 🔴 阻断 | 补充 SKU 或从样本中移除该行 |
| 4 | 产品名为空 | 旧系统数据不完整 | 🔴 阻断 | 补充产品名或从样本中移除该行 |
| 5 | 库存列包含中文（如"10件"、"约50"） | 旧系统库存列存储格式不规范 | 🔴 阻断 | 手工清理为纯数字；后续可考虑增加数字提取逻辑 |
| 6 | CSV 内部重复 SKU | 旧系统导出时有重复行 | 🔴 阻断 | 在 CSV 中删除重复行或合并库存数据 |
| 7 | 旧系统没有 min_stock 列 | 旧系统未设置最低库存 | 🔴 阻断 | 为样本补充 min_stock 列并填写合理值 |
| 8 | 总库存字段被误认为 current_stock | 列名如"库存量""总库存"可能与新系统 P0 字段映射混淆 | 🔴 关键 | 人工确认旧系统"库存量"含义，确保映射到正确的 current_stock |
| 9 | 旧系统导出字段过多（30+ 列） | 旧系统导出全部字段 | 🟡 不影响 | 系统自动忽略未识别字段，不报错 |
| 10 | 供应商/品牌字段名混乱 | 旧系统可能用"供货商""厂商"等不同命名 | 🟡 可能丢失 | 将旧系统列名改为 supplier/brand；后续可考虑增加别名映射 |
| 11 | 已存在 SKU 被跳过（首次导入不会有此问题） | create_only 模式预期行为 | 🟢 正常 | 确认 skipped 而非错误，此为预期行为 |
| 12 | 数字字段带千分位分隔符（如 1,000） | 旧系统数字格式化 | 🔴 可能阻断 | 在 CSV 中去除逗号，改为纯数字 |
| 13 | CSV 带 BOM 头 | 某些旧系统导出 UTF-8 BOM | 🟢 不影响 | 通常不影响解析，如有则记录 |
| 14 | 换行符不一致（CRLF/CR/LF） | 旧系统在不同平台导出 | 🟢 通常不影响 | CSV 解析库通常兼容，如有异常则统一换行符 |
| 15 | 备注字段包含换行符 | 旧系统备注列可能有嵌入换行 | 🟡 可能影响 | CSV 解析可能拆分为多行，如发现问题则需预处理 |

## 九、不建议现在做的事情

| # | 不建议做 | 原因 |
|---|----------|------|
| 1 | 全量导入 | 先小批量验证，确认无误后再扩大范围 |
| 2 | 直接覆盖已有产品 | 当前仅支持 create_only，不会覆盖，但也不建议手工强改 |
| 3 | 开放 overwrite 模式 | 尚未实现，且直接覆盖有数据安全风险 |
| 4 | 开放 update_existing 模式 | 尚未实现，需配合变更审计 |
| 5 | 批次撤销 | 尚未实现，误操作后只能通过数据库备份恢复 |
| 6 | 把异地库存合并到 current_stock | 违反库存口径硬约束 |
| 7 | 把总可售库存合并到 current_stock | 违反库存口径硬约束 |
| 8 | 跳过备份直接导入 | 数据安全底线要求 |
| 9 | 使用 viewer 账号执行导入 | 权限系统禁止，viewer 无导入权限 |
| 10 | 在 CSV 预览未通过时强行调用导入 API | 后端会重新校验，有 error 会拒绝写库 |

## 十、通过标准

小批量迁移验收判定**通过**的条件：

| # | 判定标准 | 说明 |
|---|----------|------|
| 1 | 10~30 条样本可完成预览 | 文件上传成功，预览 API 返回正常 |
| 2 | P0 字段识别正确 | SKU、产品名、current_stock、min_stock、category、unit 全部识别 |
| 3 | 阻断 error 可解释 | 如有 error，原因明确且可通过修正 CSV 消除 |
| 4 | warning 不影响导入 | 有 warning 时 can_import 仍为 true |
| 5 | 正式导入结果与预期一致 | created_count / skipped_count / error_count 与实际数据匹配 |
| 6 | Products 页面数据正确 | 所有字段值与 CSV 一致，库存状态正确 |
| 7 | AuditLog 可追溯 | 有"批量导入"记录，操作人正确 |
| 8 | 库存口径无误 | 异地/虚拟/总可售库存未写入 current_stock |
| 9 | 未出现半批写入 | 无事务不完整情况 |
| 10 | 未出现覆盖风险 | 已存在 SKU 被 skipped 而非覆盖 |

#### 通过判定

- **10 项全部满足** → ✅ 通过，可考虑更大规模导入
- **8~9 项满足** → ⚠️ 有条件通过，需修复不满足项后重试
- **不到 8 项满足** → ❌ 不通过，需排查根本原因

## 十二、最终建议

1. **只有真实旧系统样本 CSV 小批量验收通过后，才建议考虑更大规模导入**
2. **正式替换旧系统前，必须保留旧系统备份和新系统数据库备份**
3. **首次大规模导入建议分批次进行**（如每次 50~100 条），便于快速定位问题
4. **导入后 1~2 天内重点监控低库存预警和产品编辑功能是否正常**
5. **如旧系统字段名与新系统差异较大，建议后续增加字段别名映射功能**（可放在后续 Step 中规划）
6. **如旧系统编码为 GBK/Big5 等非 UTF-8，建议后续考虑增加编码自动检测功能**
