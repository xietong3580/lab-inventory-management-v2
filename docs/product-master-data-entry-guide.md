# 产品主数据正式录入指南

> 版本：V2/V3  
> 更新时间：2026-07-05  
> 适用范围：从旧系统切换到新系统或首次正式录入产品资料时，按统一规范填写产品主数据  

---

## 一、文档目的

本文档用于指导库存自动化管理系统中产品资料的正式录入、核对和后续维护。制定统一的录入规范，可以在以下方面带来帮助：

- 减少 SKU 重复、分类错乱、库位混乱等问题
- 确保库存数量与实际情况一致
- 便于后续搜索、筛选、导出和核对
- 降低后续维护和交接成本
- 为后续商业化扩展打好的数据基础

本文档面向实际操作产品的管理员和录入人员，不是开发技术文档。

---

## 二、什么是产品主数据

产品主数据是指每个产品在系统中的基本资料记录，包括以下字段：

### 库存管理核心字段（建议优先填写准确）

| 字段 | 系统内名称 | 说明 |
|------|-----------|------|
| SKU 编码 | sku | 产品唯一标识，用于搜索、对账、导入导出 |
| 产品名称 | name | 产品中文名称，建议使用规范全称 |
| 库存分类 | category | 2楼库存、3楼库存、刘晓冬安捷伦库存、尚工安捷伦库存 |
| 存储位置 | location | 精确到货架的库位编号 |
| 当前库存 | currentStock | 当前实际库存数量 |
| 最低库存 | minStock | 低于此数量时系统触发低库存预警 |
| 单位 | unit | 个、盒、瓶、包、套 |

### 管理辅助字段（建议后续补充）

| 字段 | 系统内名称 | 说明 |
|------|-----------|------|
| 品牌 | brand | 如安捷伦、赛默飞等 |
| 规格 | specification | 如 1.5×100mm、500ml |
| 供应商 | supplier | 如上海某某化工 |
| 备注 | notes | 其他需要记录的信息 |

### 可选字段（不影响库存管理）

| 字段 | 系统内名称 | 说明 |
|------|-----------|------|
| 采购价 | purchasePrice | 采购单价，可留空 |
| 售价 | salePrice | 销售单价，可留空 |

核心字段决定了一个产品能否正常参与库存管理和预警；管理辅助字段帮助后续筛选和核对；价格字段暂时不影响库存计算，可以后续再补充。

## 三、正式录入前准备

在正式开始录入产品之前，建议完成以下准备工作：

1. **旧系统数据备份**：将旧系统中的产品列表导出或截图保存，作为核对参考
2. **新系统数据库备份**：在系统设置中创建一次数据库备份
3. **确认录入人员**：明确谁来录入、谁来核对，避免多人同时操作造成混乱
4. **确认分类和库位规则**：事先确定好产品应该归入哪个库存分类、放在哪个库位，不要一边录入一边改规则
5. **先少量测试**：建议先录入 3-5 个产品熟悉流程，确认无误后再批量录入
6. **保持耐心**：正式录入是细致活，宁愿慢一点，不要为了赶进度导致大量数据错误

## 四、字段填写规范

以下表格按字段逐一说明填写规范：

| 字段名 | 是否建议必填 | 填写规范 | 示例 | 注意事项 |
|--------|-------------|----------|------|----------|
| SKU 编码 | **是** | 全局唯一，建议统一格式，如 PRD-YYYYNNNN 或品牌缩写+编号 | `PRD-2026001`、`AGILENT-001` | 不要多个产品共用一个 SKU；录入后不要频繁修改；不要用太随意的中文短语当 SKU |
| 产品名称 | **是** | 使用规范全称，建议统一命名风格，比如"品牌+品名+规格" | `安捷伦色谱柱 ZORBAX 4.6×150mm` | 不要只写简称；不要写"耗材一""试剂三"等无法辨识的名称 |
| 库存分类 | **是** | 从系统下拉列表选择：2楼库存、3楼库存、刘晓冬安捷伦库存、尚工安捷伦库存 | `2楼库存` | 选择分类后库位会自动联动；不确定分类的产品先标记，后续确认再改 |
| 存储位置 | **是** | 根据库存分类从库位下拉选择，2楼有 A1-F4 共 24 个货架，3楼有 3-1 至 3-5 | `A1`、`3-2` | 分类和库位要对应；不要为了方便全部放到同一个库位；专用区域不需要选具体货架 |
| 当前库存 | **是** | 建议以实物盘点或旧系统核对结果为准如实填写 | `15` | 不确定库存不要随意填；如果旧系统有库存数据，先核对再填；可以直接填 0 表示当前无库存 |
| 最低库存 | **是** | 根据采购周期、使用频率和重要程度综合设定 | `10` | 设太高会导致大量低库存预警；设太低起不到预警作用；后续可根据实际消耗调整 |
| 单位 | **是** | 从下拉选择：个、盒、瓶、包、套 | `瓶` | 选最符合实际使用习惯的单位；一个产品的单位录入后尽量不要改 |
| 品牌 | 建议填写 | 统一品牌名称写法，同一品牌不要有多种写法 | `安捷伦` | 不要写"Agilent"又写"安捷伦"；品牌字段可用于筛选和统计 |
| 规格 | 建议填写 | 产品的主要规格参数 | `1.5×100mm`、`500ml` | 有助于区分同名不同规格的产品 |
| 供应商 | 建议填写 | 供应商全称或常用简称 | `上海某某化工有限公司` | 同一供应商名称统一，便于后续统计 |
| 采购价 | 可选 | 数字，可留空 | `12.50` | 不要用 0 表示未知价格；暂时不知道就留空 |
| 售价 | 可选 | 数字，可留空 | `25.00` | 同上 |
| 备注 | 可选 | 自由文本，记录需要关注的信息 | `已开封，剩余约半瓶` | 不要写太长的备注；重要信息优先放在前面 |

## 五、SKU 编号建议

### SKU 的作用

SKU（Stock Keeping Unit）是产品在系统中的唯一标识，将在以下场景中频繁使用：

- 搜索和筛选产品
- 出入库记录关联
- CSV 导出与外部数据对账
- 台账和操作日志追溯
- 后续可能的数据导入和系统对接

### 推荐编号方案

**方案一：统一编号**

格式：`PRD-YYYYNNNN`（PRD 前缀 + 年份 + 4 位流水号）

- 示例：`PRD-2026001`、`PRD-2026125`
- 优点：简单统一，不会重复，适合产品种类较多的情况
- 缺点：看不出产品类别和品牌

**方案二：品牌/类别 + 编号**

格式：品牌缩写 + 连字符 + 流水号

- 示例：`AGILENT-001`（安捷伦产品）、`SIGMA-023`（Sigma 产品）
- 优点：一看就知道是哪家品牌的产品
- 缺点：品牌名可能有多种写法，需要先统一

**方案三：沿用旧系统编号**

如果当前旧系统（或腾讯文档）已有产品编号且比较规范，可以直接沿用。

- 示例：`HG-2024-058`（化工类，2024年，第58号）
- 优点：迁移成本低，旧数据直接对应
- 缺点：旧编号可能不规范，需要检查

### 关于无货号的产品

如果产品确实没有货号（如某些散装耗材），建议使用内部编号，不应留空 SKU。例如：

- `LEGACY-NOCODE-0001`
- `N/A-2026-001`

产品名称保持真实名称，方便后续识别和管理。

### SKU 使用红线

- 不要多个产品共用一个 SKU（系统会阻止重复）
- 不要录入后随意修改 SKU，会破坏历史记录的关联
- 不要用太随意的中文短语当 SKU（如 `那个大的瓶子`）
- 不要用可能产生歧义的编号

## 六、库存分类与库位规则

### 当前系统可用分类与对应库位

| 库存分类 | 可选库位 | 说明 |
|----------|----------|------|
| 2楼库存 | A1-A4、B1-B4、C1-C4、D1-D4、E1-E4、F1-F4 | 共 24 个货架位，适合一般耗材和试剂 |
| 3楼库存 | 3-1、3-2、3-3、3-4、3-5 | 共 5 个库位，适合设备或大件物品 |
| 刘晓冬安捷伦库存 | 专用区域（固定） | 安捷伦产品专用库存，由刘晓冬管理 |
| 尚工安捷伦库存 | 专用区域（固定） | 安捷伦产品专用库存，由尚工管理 |

### 分类和库位规则

- 选择库存分类后，库位下拉会自动显示对应分类下的可选库位
- 安捷伦相关产品请归入对应的专用库存分类
- 2楼和3楼的普通产品请按实际存放位置选择库位
- 产品分类录入后可以修改，但修改分类后库位会重置，需要重新选择
- 不确定分类的产品先选一个最接近的分类，做好标记，后续核对时再调整
- 不要为了方便把所有产品都放在同一个库位（如全部放在 A1），会失去库位管理的意义

## 七、当前库存与最低库存填写建议

### 当前库存

- **优先使用实物盘点结果**：如果最近做过实物盘点，以盘点结果为准
- **参考旧系统数据**：如果旧系统中有库存数据，先核对，确认准确再填入
- **不确定的库存先标记**：不要随意填一个数字，标注后在核对阶段确认
- **可以填 0**：如果确定该产品当前没有库存，直接填 0

### 最低库存

最低库存是低库存预警的基础，设置要合理：

| 产品类型 | 建议最低库存 | 理由 |
|----------|-------------|------|
| 常用耗材（每周消耗） | 2-4 周的用量 | 采购周期短，不需囤太多 |
| 不常用耗材 | 1-2 个 | 偶尔使用，保持基本库存即可 |
| 关键试剂（不可断货） | 至少 1 个月的用量 | 断货影响实验进度 |
| 设备配件 | 0-1 个 | 坏了再买，不需常备 |
| 高价值产品 | 0-1 个 | 减少资金占用 |

### 注意事项

- 最低库存不是越高越好：设太高会导致大量"低库存预警"，反而淹没真正需要关注的产品
- 最低库存设太低：失去了预警的意义，等到库存为 0 才发现
- 修改最低库存不会直接改变当前库存，只是影响预警判断
- 建议录入初期先按经验设置，后续根据实际消耗数据调整

---

## 八、价格字段填写建议

### 当前阶段

- 采购价和售价不是库存管理的核心字段
- 如果暂时不知道准确价格，**留空即可**
- **不建议用 0 表示未知价格**：0 表示免费或零价格，留空才表示未知
- 价格缺失不会影响产品保存、库存管理和预警

### 后续阶段

- 如果后续需要做采购成本统计、销售报表、产品报价等功能，可以逐步补齐价格
- 补齐价格时建议核对实际采购记录或发票
- 价格变动建议在备注中记录原因和时间

---

## 九、录入顺序建议

建议按照以下顺序逐步录入产品，不要试图一次性全部录完：

| 步骤 | 内容 | 说明 |
|------|------|------|
| 1 | 确定分类和库位规则 | 和相关负责人确认后固定下来，中途不要随意改 |
| 2 | 先录常用产品 | 日常使用频率高的产品优先录入，确保基本运转 |
| 3 | 再录高价值和关键产品 | 价格高或不可断货的产品，需准确填写库存和最低库存 |
| 4 | 再录历史库存产品 | 当前库存较少或不常用的产品 |
| 5 | 每录入一批（如 10-20 个）检查核对状态 | 打开产品核对概览，确认没有遗漏 |
| 6 | 每天录入结束后创建备份 | 打开系统设置 → 创建数据库备份 |

### 录入节奏建议

- 每天录入 20-50 个产品比较合适，不会太累也容易保证质量
- 录入 1-2 小时后休息一下，避免疲劳导致录入错误
- 不要为了追求速度而牺牲准确性

---

## 十、录入后的核对清单

每批产品录入完成后，建议逐项检查：

### 单产品检查

| 检查项 | 如何检查 |
|--------|----------|
| 产品名称是否清楚 | 看一遍名称，能否一眼认出是什么产品 |
| SKU 是否重复 | 系统会自动检查，红色提示表示重复 |
| 分类和库位是否正确 | 确认分类和库位与实际存放位置一致 |
| 当前库存是否准确 | 对比旧系统或盘点结果 |
| 最低库存是否合理 | 太低则起不到预警作用，太高则造成假预警 |
| 价格如果填写了是否合理 | 不要出现 0 元但实际有价格的情况 |

### 整批检查

| 检查项 | 如何检查 |
|--------|----------|
| 核对状态 | 打开产品核对概览，确认"需核对"数量是否合理 |
| 总数量 | 产品总数是否与旧系统或预期一致 |
| 低库存预警 | 打开低库存预警页，确认预警列表与预期一致 |
| 导出核对 | 导出 CSV，与旧系统或腾讯文档逐条比对 |

### 核对状态参考

产品管理页面中的核对概览会显示三个数字：

- **信息完整**：核心字段完整，可以正式使用
- **建议补充**：缺少辅助字段（如库位、单位），建议后续补齐
- **需核对**：缺少关键字段（如 SKU、产品名称），需要立即处理

核对状态不会阻止产品保存，只是帮助管理员了解录入质量。

## 十一、常见错误与处理建议

### SKU 重复

- **现象**：录入时提示 SKU 已存在
- **原因**：两个产品用了同一个 SKU，或误操作重复添加
- **处理**：检查是否真的是同一个产品；如果是不同产品，为其中一个修改 SKU；如果是重复录入，删除多余的那个

### 产品名称太短或不规范

- **现象**：名称只有两三个字，或者写的是内部代号
- **影响**：后续搜索困难，其他人看不懂
- **处理**：编辑产品，补充完整的产品名称

### 库位随意填写

- **现象**：所有产品都放在同一个库位，或库位与分类不匹配
- **影响**：失去库位管理的作用，找产品时还是要去翻货架
- **处理**：逐批修正库位，按实际存放位置填写

### 把未知价格填成 0

- **现象**：采购价或售价填了 0
- **影响**：0 表示免费，后续做成本统计时数据不准确
- **处理**：编辑产品，将 0 改为留空

### 当前库存填错

- **现象**：录入后发现库存数字和实际对不上
- **处理**：
  - 如果还没有出入库记录：直接编辑产品修改库存
  - 如果已有出入库记录：不要直接改库存，通过入库或出库来调整
  - 建议先查看产品台账，确认历史变动

### 最低库存设置过高导致大量预警

- **现象**：录入完成后低库存预警页面出现大量预警
- **处理**：逐批调整最低库存，确保只对真正需要关注的产品设置合理的阈值

### 录入后发现分类不合适

- **现象**：产品的实际存放位置与分类不匹配
- **处理**：编辑产品修改分类；注意修改分类后库位会重置，需要重新选择

## 十二、正式切换旧系统前的产品数据验收

在所有产品录入完成后、正式切换到新系统前，建议完成以下验收：

| 验收项 | 具体要求 |
|--------|----------|
| 产品总数对比 | 新系统产品数量与旧系统（或腾讯文档）一致或合理偏差 |
| 各分类产品数量 | 2楼库存、3楼库存等各分类下的产品数量与实际情况一致 |
| 重点产品库存抽查 | 随机抽取 10-20 个常用产品，逐一核对当前库存 |
| 低库存产品核实 | 低库存预警列表中的产品确实库存不足或接近最低库存 |
| SKU 唯一性 | 导出 CSV 检查是否有 SKU 为空或重复 |
| 关键产品确认 | 老板或管理员确认高价值、关键产品的库存数据 |
| 核对状态检查 | "需核对"产品数量不超过总数的 5%，或已确认可接受 |
| 旧系统保留 | 旧系统数据保留只读一段时间，作为最后的安全参考 |

## 十三、后续维护原则

### 新增产品

- 新到货的产品及时录入系统
- 录入时遵循本文档的字段规范
- 录入后检查核对状态

### 修改产品

- 编辑产品信息后核对状态会自动更新
- 修改 SKU 要慎重，会影响历史记录关联
- 大批量修改前先创建数据库备份

### 产品停用

- 不建议直接删除不再使用的产品（历史出入库记录会丢失关联）
- 可将库存调整为 0，在备注中注明"已停用"
- 或保留数据，后续如有需要可扩展产品状态字段

### 定期维护

- 建议每月或每季度检查一次"需核对"产品列表
- 定期检查低库存预警阈值是否仍然合理
- 库存有大的变动后（如盘点），及时更新系统中的库存数据
- 每次批量操作后创建数据库备份

```
  总数对账 → 重点抽查 → 管理员确认 → 保留旧系统只读

日常维护：
  新产品录入 → 定期检查 → 定期备份 → 数据调整需留痕
```
