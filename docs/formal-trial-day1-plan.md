# 正式试用首日操作方案与异常处理手册

## 1. 首日试用目标

- **不追求一天内完全替代旧系统**。
- 目标是验证真实工作流是否顺畅：查询 → 筛选 → 出入库 → 核对 → 审计。
- 首日只做少量、低风险、可核对的真实操作。
- 旧系统继续保留并行，不关闭、不删除、不迁移额外数据。

## 3. 首日建议操作范围

### 以查为主

| 操作 | 说明 |
|---|---|
| 按产品货号搜索 | 输入货号如 CL420，确认返回 2 条 |
| 按产品名称搜索 | 输入中文或英文名称 |
| 品牌多选筛选 | 勾选 1-2 个品牌，确认筛选结果 |
| 库存分类多选筛选 | 勾选"2楼库存"，确认 ~181 条 |
| 库位多选筛选 | 勾选 E2，确认 24 条 |
| 组合筛选 | 品牌 + 库存分类 + 库位同时生效 |
| 重置筛选 | 恢复 343 条 |

### 精准少量写

| 操作 | 限制 |
|---|---|
| 首批真实出入库 | 只选 1-3 个低风险产品 |
| 产品选择 | 选用户自己熟悉、库存数量容易核对的产品 |
| 入库数量 | 不超过 10，便于心算核对 |
| 出库数量 | 不超过当前库存的 20%，确保不触发库存不足 |
| 批量操作 | 首日不建议 |

## 4. 首日推荐操作顺序

| 步骤 | 操作 | 验收点 |
|---|---|---|
| 1 | 登录 admin 或 tong 账号 | 看到 Dashboard |
| 2 | 查看 Dashboard 基线 | 343 / 163 |
| 3 | Products 搜索 3-5 个常用货号 | 都能搜到 |
| 4 | Products 搜索 3-5 个常用名称 | 都能搜到 |
| 5 | 用分类/库位筛选核对 | 筛选结果合理 |
| 6 | 选 1 个产品做小额入库（≤10） | 库存增加、Dashboard 联动 |
| 7 | 核对库存、台账、AuditLog | 入库记录可查 |
| 8 | 选 1 个产品做小额出库 | 库存减少、Dashboard 联动 |
| 9 | 再次核对库存、台账、AuditLog | 出库记录可查 |
| 10 | 必要时演示撤销（首日不建议频繁撤销） | 撤销后库存回滚 |
| 11 | 导出当前筛选结果 | 确认弹窗显示正确 |
| 12 | 当天结束后创建备份 | 备份创建成功 |

## 5. 旧系统并行对账方法

- **旧系统至少并行 1-2 周**，不要过早关闭。
- 每天选 5-10 个高频产品抽查对比：

| 对比字段 | 新系统 | 旧系统 |
|---|---|---|
| 产品名称 | 产品管理表格 | 旧系统产品列表 |
| 货号/SKU | 产品管理表格 | 旧系统货号列 |
| 库位 | 产品管理表格 | 旧系统库位列 |
| 当前库存 | 产品管理表格 | 旧系统库存数 |
| 最低库存 | 产品管理表格 | 旧系统预警阈值 |

- 新系统发生真实出入库后，旧系统是否同步记录由用户按实际流程决定。
- **不要在两个系统同时随意改同一产品**，避免对账困难。
- 每天记录差异，不要当场乱改大量数据。

- [ ] 低库存数量是否合理
- [ ] Products 是否能正常搜索

- [ ] AuditLog 是否记录了当天操作
- [ ] 是否出现负库存
- [ ] 是否出现误操作
- [ ] 是否已经创建当天备份

## 7. 异常处理原则

1. **发现异常先停止操作**，不要继续。
2. 不要连续点击。
3. 不要清空数据。
4. 不要恢复备份。
5. 不要手动改数据库。
6. 先**截图**记录。
7. 记录：操作人、时间、页面、产品货号、产品名称、异常现象。
8. 保留浏览器页面，不要急着刷新。
9. 通知管理员后再处理。

## 8. 常见异常与处理建议

| 现象 | 可能原因 | 处理方式 |
|---|---|---|
| 搜不到产品 | 筛选条件未重置 | 先点"重置筛选"，再按货号/名称分别搜索 |
| 库存数量不对 | 可能已被出入库修改 | 先查该产品的台账和出入库记录，不要直接编辑库存 |
| 误做入库/出库 | 操作失误 | 优先使用撤销功能，不要手动改产品库存 |
| 导出数量不对 | 当前处于筛选状态 | 检查导出弹窗提示是"筛选结果"还是"全部产品" |
| 普通员工不能操作 | 权限限制 | viewer 只能查看，这是正常表现 |
| 页面数据没刷新 | 前端缓存 | 手动刷新页面，再核对 Dashboard/Products |
| 严重异常 | 库存或数据异常 | **停止使用新系统**，保留现场，考虑恢复备份 |

## 9. 回滚触发条件

以下任一情况出现，建议回滚：

- 大量库存数量异常（≥5 个产品）
- 多个产品库存被错误修改
- 出入库记录与库存无法对应
- 系统无法正常登录或关键页面无法访问
- 误执行清空、导入、恢复等危险操作
- 管理员判断继续使用风险较高

## 10. 回滚前必须做的事

1. **先不要立即恢复**。
2. 截图记录异常现象。
3. 记录当前时间。
4. 记录当前 Git 节点。
5. 复制当前数据库做现场备份：
   ```bash
   cp apps/api/inventory.db apps/api/backups/incident_<日期时间>.sqlite
   ```
6. 确认正式试用前最终基线备份仍存在且 integrity_check=ok。
7. 确认后，再通过系统设置页执行恢复。

**可用恢复备份：**

| 备份文件 | 说明 |
|---|---|
| `inventory_backup_before_formal_trial_20260711_203256.sqlite` | 正式试用前干净基线 |
| `inventory_backup_before_step_10_29B_20260711_195946.sqlite` | 闭环演练前干净基线 |

## 11. 首日成功标准

- [ ] 查询顺畅（货号、名称、品牌、分类、库位）
- [ ] 筛选顺畅（多选、组合、重置）
- [ ] 少量真实出入库准确（数量、台账、审计一致）
- [ ] Dashboard/Products/Transactions/AuditLog 联动正常
- [ ] 没有误操作或误修改
- [ ] 旧系统对账无明显差异
- [ ] 当天结束备份成功

## 12. 不建议首日做的事

- ❌ 批量改大量产品
- ❌ 大规模出入库
- ❌ 清空数据
- ❌ 重新导入
- ❌ 手动改数据库
- ❌ 删除备份
- ❌ 关闭旧系统
- ❌ 让普通员工（viewer）参与写操作

## 13. 管理员首日简版流程

```
1. 登录
2. 看 Dashboard → 确认 343 / 163
3. 搜产品 → CL420 (2条) / Measuring (1条) / 常用中文名
4. 筛选 → 品牌 / 分类 / 库位 各试一个
5. 做 1 条入库 → 选熟悉产品 + 少量 + 备注"首日测试入库"
6. 做 1 条出库 → 选同一产品 + 少量 + 备注"首日测试出库"
7. 查台账 → 确认入库/出库记录完整
8. 查审计 → 确认操作已记录
9. 导出 → 确认弹窗提示范围
10. 备份 → 创建当天备份
11. 记录问题 → 有异常及时反馈
```
