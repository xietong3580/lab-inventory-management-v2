# 正式导出、备份与迁移验收清单

> 本文档用于正式替换旧库存系统前的操作流程固化。
> 当前系统处于**开发/验收阶段**，尚未正式上线。
> 本文档不替代上线部署流程，真正上线前仍需独立部署检查与回滚方案。

---

## 1. 使用场景

本文档适用于以下场景：

- 正式导出产品库存数据至 CSV 供旧系统迁移核对
- 在操作数据库备份前后进行安全确认
- 旧系统数据迁移至新系统前的字段口径核对
- 正式替换旧库存系统前的最终验收
- 导出或备份过程中出现异常时的排查参考

## 3. 正式导出前准备

在执行正式导出操作前，按以下顺序确认：

- [ ] **Git 工作区 clean**：执行 `git status -sb`，确认无未提交改动
- [ ] **前后端服务正常**：确认开发服务器或生产部署可访问
- [ ] **admin 登录**：使用管理员账号登录系统
- [ ] **Products 页面数据正常**：进入产品管理页，确认产品列表加载无报错
- [ ] **Settings 安全检查可运行**：进入系统设置 → "运行安全检查"，确认接口返回正常
- [ ] **备份目录不提交到 Git**：确认 `.gitignore` 已排除 `*.db`、`*.sqlite`、`*.csv`、`backups/` 目录

## 4. 安全检查流程

### 4.1 触发方式

**方式一：Products 页面导出触发**

1. 进入产品管理页
2. 点击"导出 CSV"
3. 系统自动调用 `GET /api/maintenance/preflight`
4. 弹出"导出前安全检查"模态框展示结果

**方式二：Settings 页面手动触发**

1. 进入系统设置
2. 在"数据安全与备份"区域点击"运行安全检查"
3. 结果展示在按钮下方

### 4.2 检查项目

| 检查项 | 说明 |
|---|---|
| 数据库文件是否存在且可读 | 数据库文件路径、权限检查 |
| 备份目录是否存在且可写 | `apps/api/backups/` 目录状态 |
| 产品数量 | `products` 表记录数 |
| 交易数量 | `transactions` 表记录数 |
| 审计日志数量 | `audit_logs` 表记录数 |
| 负库存 | `current_stock < 0` 的产品数 |
| 缺失 product_id | `transactions` 中 `product_id IS NULL OR 0` 的记录数 |
| 孤立 product_id | `transactions` 中 `product_id` 指向不存在产品的记录数 |
| 重复 SKU | `products` 表中 SKU 重复的产品数 |

### 4.3 结果判定

| 状态 | 含义 | 建议操作 |
|---|---|---|
| `ok` ✅ | 所有检查通过 | 可以安全导出 |
| `warning` ⚠️ | 存在警告项 | 允许导出，建议查看警告明细后再确认 |
| `error` ❌ | 存在错误项 | 建议先处理错误再导出，仍有高风险可手动跳过 |

## 5. admin 创建备份后导出流程

> 以下流程要求当前登录用户角色为 **admin**。

1. 进入产品管理页
2. 调整筛选条件，确认要导出的产品范围
3. 点击"导出 CSV"
4. 系统弹出"导出前安全检查"模态框，展示 preflight 结果
5. 点击 **"创建备份后导出"** 按钮
6. 系统调用 `POST /api/maintenance/backups`，在 `apps/api/backups/` 生成 `inventory_backup_YYYYMMDD_HHMMSS.sqlite`
7. 备份成功后，弹窗自动关闭，CSV 文件自动下载
8. 进入系统设置 → 备份记录区域，刷新后确认最新 `.sqlite` 文件出现在列表中

**关键约束：**

- 备份失败时，弹窗**不关闭**，CSV **不下载**，显示红色错误提示
- 按钮在备份过程中显示"备份中..."且禁用，防止重复点击
- 备份成功后才执行 CSV 导出

## 7. 产品库存 CSV 字段口径

导出的 CSV 文件包含以下 14 列，字段顺序固定：

| # | CSV 列名 | 对应数据库字段 | 说明 |
|---|---|---|---|
| 1 | 产品ID | `products.id` → `prod-XXXXXX` 格式 | 系统内部 ID |
| 2 | SKU | `products.sku` | 货号编码 |
| 3 | 产品名称 | `products.name` | 产品名称 |
| 4 | 分类 | `products.category` | 库存分类 |
| 5 | 品牌 | `products.brand` | 品牌 |
| 6 | 规格 | `products.specification` | 规格型号 |
| 7 | 存储位置 | `products.location` | 库位 |
| 8 | 单位 | `products.unit` | 计量单位 |
| 9 | 当前库存 | `products.current_stock` | 当前库存数量 |
| 10 | 最低库存 | `products.min_stock` | 最低库存预警阈值 |
| 11 | 库存状态 | 实时计算（`current_stock <= min_stock` → "低库存"，否则"正常"） | 库存状态 |
| 12 | 供应商 | `products.supplier` | 供应商名称 |
| 13 | 备注 | `products.notes` | 备注信息 |
| 14 | 更新日期 | `products.last_updated` | YYYY-MM-DD 格式 |

**字段口径约束：**

- 所有字段均对应数据库真实列，不包含 UI 临时字段
- 不包含内部调试字段
- 不包含数据库文件路径或备份文件路径
- 空字段允许为空字符串，不硬造默认值
- CSV 使用 BOM (`﻿`) + UTF-8 编码，兼容 Excel 直接打开
- 字段顺序固定，用于旧系统迁移核对和人工比对

## 8. 备份文件说明

### 8.1 两种备份格式

| 格式 | 文件名示例 | 生成方式 | 生成时间节点 |
|---|---|---|---|
| 旧格式 `.db` | `inventory-backup-2026-06-27-224218.db` | Settings → 立即备份（`POST /api/backups/manual`） | Step 8 阶段 |
| 新 maintenance `.sqlite` | `inventory_backup_20260630_212732.sqlite` | Settings → 创建备份 / Products → 创建备份后导出（`POST /api/maintenance/backups`） | Step 10-5B 阶段 |

### 8.2 备份文件管理

- 备份文件存储在 `apps/api/backups/` 目录
- Settings → 备份记录区域同时显示 `.db` 和 `.sqlite` 文件
- 按文件修改时间倒序排列（最新在最上）
- `.sqlite` 文件可通过 Settings 下载按钮下载
- 备份目录不提交到 Git（`.gitignore` 已排除）
- 备份文件命名包含时间戳，不会互相覆盖

### 8.3 备份文件校验

每个备份文件在列表展示和下载前都会执行 `PRAGMA integrity_check`，校验不通过的文件：
- 列表中标记校验失败状态
- 下载时拒绝提供并返回错误

## 10. 异常处理

| 异常场景 | 排查与处理 |
|---|---|
| **安全检查失败**（preflight 返回 error） | 查看弹窗中 errors 明细；优先处理重复 SKU、负库存等数据问题；处理后再试 |
| **备份失败**（"创建备份后导出"报错） | 检查 Settings 页面备份功能是否正常；确认磁盘空间充足；确认 `apps/api/backups/` 目录可写；查看后端日志 |
| **CSV 未下载**（备份成功但无文件） | 检查浏览器下载设置是否拦截；检查浏览器控制台是否有 JS 错误；手动再次点击导出 |
| **Settings 看不到新 `.sqlite` 备份** | 刷新 Settings 页面（重新调用 `GET /api/backups`）；确认后端服务已重启（若修改过代码）；确认文件名格式为 `inventory_backup_YYYYMMDD_HHMMSS.sqlite` |
| **`.sqlite` 无法下载** | 确认文件存在于 `apps/api/backups/`；确认文件名匹配正则 `inventory_backup_\d{8}_\d{6}\.sqlite`；确认后端已更新至 `00c902e` |
| **Git 工作区出现数据文件** | 不要 `git add` 数据文件；在 `.gitignore` 中确认 `*.db`、`*.sqlite`、`*.csv`、`backups/` 已排除；执行 `git checkout -- <file>` 恢复或手动删除 |
| **不小心生成测试 CSV / 备份文件** | CSV 文件直接删除即可；备份文件如需清理，进入 `apps/api/backups/` 手动删除旧文件（保留最后一次正式备份） |

## 11. 正式替换旧系统前最终确认

> ⚠️ 此清单在**正式替换旧系统**前逐项确认，所有项必须通过。

### 数据备份确认

- [ ] 已完成最新数据库备份（`.sqlite` 格式，文件名含当前日期）
- [ ] 备份文件已通过 `PRAGMA integrity_check` 验证
- [ ] 备份文件已保存至安全位置（不随项目目录删除而丢失）

### CSV 导出确认

- [ ] 已导出产品库存 CSV（14 列完整）
- [ ] 已人工核对产品数量：CSV 行数 = Products 页面显示的产品总数
- [ ] 已人工核对库存总量：抽查 3-5 个产品，CSV 中当前库存 = 页面显示库存

### 数据抽查

- [ ] 已抽查低库存产品（状态=低库存）：验证 `current_stock <= min_stock`
- [ ] 已抽查库位字段：确认 location 不为空的产品有真实库位信息
- [ ] 已抽查 SKU：确认 SKU 唯一、格式正常

### 回退准备

- [ ] 旧系统仍可访问，数据完整
- [ ] 已记录旧系统当前数据快照（截图或导出）
- [ ] 有明确的回退路径和负责人

### 新系统状态

- [ ] 新系统 15 项核心链路通过人工验收（见第 9 节）
- [ ] Git 工作区 clean（`git status -sb` 输出 `## main...origin/main`）
- [ ] 已知问题无阻塞项
