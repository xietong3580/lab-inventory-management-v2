# 正式数据导入前检查清单

## 适用范围

- 用于从旧库存系统正式导入产品数据前的各项检查。
- 不用于测试文件随意导入。
- 不替代人工核对原始数据与旧系统记录。

## 禁止事项

- 禁止直接跳过预览执行正式导入。
- 禁止在未创建数据库备份时导入。
- 禁止导入来源不确定的 CSV 文件。
- 禁止导入包含大量错误或警告但未经人工确认的文件。
- 禁止提交 CSV / .db / .sqlite / backups 到 Git。

---

## 第 0 步：环境确认

- [ ] Git 工作区干净（`git status` 无未提交文件）
- [ ] 最新代码已推送到远程
- [ ] `npm run build` 通过
- [ ] `npm run check:api-config` 通过
- [ ] 后端使用端口 8000（`uvicorn main:app --host 127.0.0.1 --port 8000`）
- [ ] 生产部署前必须配置环境变量 `INVENTORY_JWT_SECRET_KEY`（开发可用默认值）
- [ ] 前端运行在 5173

## 第 1 步：CSV 文件确认

- [ ] CSV 文件是最终版本（非测试文件或做过改动前的旧版）
- [ ] 文件编码支持 UTF-8 / UTF-8-BOM / GBK / GB18030（系统自动检测）
- [ ] 数据行数不超过 1000 行（系统限制）
- [ ] 文件大小不超过 2 MB
- [ ] 表头必须包含「产品名称」列和「当前库存」列
- [ ] 库存列必须是**本地真实库存**（不是总可售库存、异地库存或虚拟库存）
- [ ] SKU 字段已确认：如有空 SKU 行，系统将自动生成迁移 SKU（LEGACY-NOCODE-XXXX）
- [ ] 单位、分类、库位字段已人工确认
- [ ] 采购价、售价字段（如有）已确认数值合理
- [ ] 产品名称中无未知字符或乱码

## 第 2 步：导入预览

- [ ] 在系统「导入预览」页面上传 CSV 文件
- [ ] 预览不写入数据库（预览页面有明确提示）
- [ ] **errors 必须为 0**（有 error 的行不会导入，必须修正 CSV）
- [ ] **warnings 必须逐条人工确认**：
  - [ ] SKU 重复（CSV 内部重复或与数据库已有产品冲突）
  - [ ] 库存口径确认（当前库存列是本地真实库存）
  - [ ] 低库存预警（导入后将处于低库存状态的产品）
  - [ ] 旧系统无货号产品（将自动生成迁移 SKU）
  - [ ] 字段为空使用默认值（分类默认"耗材"、单位默认"个"等）
- [ ] 字段识别结果已确认：各列被正确映射到系统字段
- [ ] 预览界面无格式异常或数据截断

## 第 3 步：备份

- [ ] 在系统设置页创建数据库备份
- [ ] 确认备份文件已生成（备份列表中出现新文件）
- [ ] 确认备份文件大小大于 0
- [ ] 建议将备份文件下载至本地妥善保管
- [ ] 如果近期已有可用备份，可跳过新建（但建议创建最新完整备份）

## 第 4 步：是否清空当前业务数据

> 如果当前数据库中主要是测试数据，建议在正式导入前清空。

- [ ] 确认当前数据库中是否含有需要保留的正式数据
- [ ] 如需清空：
  - [ ] 先创建数据库备份（系统会自动执行）
  - [ ] 确认清空范围（产品、出入库记录、库存台账、审计日志）
  - [ ] 确认保留范围（用户账号、系统设置、备份文件）
  - [ ] 输入确认短语：`清空当前业务数据`
  - [ ] 执行清空后确认产品列表、交易记录、审计日志均为空
  - [ ] 确认审计日志中存在 `BUSINESS_DATA_CLEAR` 记录
- [ ] 如不需清空（数据库已是空库或仅有正式数据），跳过此步骤

## 第 5 步：正式导入

- [ ] 在「导入预览」页面点击「正式导入」按钮
- [ ] 勾选「我已确认上述信息，并已在导入前完成数据库备份」
- [ ] 执行正式导入
- [ ] 导入成功后立即检查：
  - [ ] 产品管理页：产品数量与 CSV 行数一致
  - [ ] 产品列表中 SKU、名称、库存、分类、库位与 CSV 一致
  - [ ] Dashboard：产品总数、正常库存数、低库存数合理
  - [ ] Alerts：低库存预警列表与 CSVA 中 current_stock ≤ min_stock 的行一致
  - [ ] AuditLog：存在 `PRODUCTS_CSV_IMPORT` 审计记录
- [ ] 导出产品 CSV，与原始文件逐行比对确认

## 第 6 步：回滚方案

> 如果导入后发现严重问题，可通过以下流程回滚。

- [ ] 确认有导入前创建的备份文件
- [ ] 备份文件的 integrity_check 为 ok
- [ ] 如需回滚，先对当前错误状态创建备份（保留问题现场以便分析）
- [ ] 使用导入前备份恢复数据库
- [ ] 重启后端服务使恢复生效
- [ ] 复查核心页面（Dashboard、产品列表、交易记录、审计日志）

---

## 风险清单

| # | 风险 | 检测方式 |
|---|------|---------|
| 1 | SKU 重复 | 导入预览会检测 CSV 内部重复 + 数据库已有 SKU |
| 2 | 产品名称重复但 SKU 不同 | 导入预览不阻断但产生 warning，需人工确认是否为不同规格 |
| 3 | 库存列口径错误（总可售而非本地库存） | 导入预览检测表头并产生口径 warning，遗漏 total_stock 列会直接拒绝 |
| 4 | 单位混乱（个/箱/kg 混用） | 人工核对 CSV 单位列 |
| 5 | 库位不规范 | 人工核对，系统允许空库位 |
| 6 | 负库存 | 导入预览产生 warning，不阻断 |
| 7 | 错把测试 CSV 当正式 CSV | 第一步人工确认文件名和来源 |
| 8 | 导入后未核对 | 第五步导出 CSV 双向比对 |

---

## 最终确认清单

执行正式导入前，请逐条核实：

- [ ] Git clean
- [ ] build 通过
- [ ] api-config 检查通过
- [ ] CSV 文件已确认是最终版本
- [ ] 已完成导入预览，errors = 0
- [ ] 所有 warnings 已人工确认
- [ ] 已在系统设置中创建数据库备份
- [ ] 已确认是否需要清空当前业务数据
- [ ] 如需清空，已输入确认短语并执行清空
- [ ] 已确认回滚方案（可用备份文件存在）
- [ ] 已了解正式导入为 create_only 模式（已有 SKU 不会覆盖）
- [ ] 正式导入后已核对 Dashboard / Products / Alerts / AuditLog

---

> 本文档作为正式导入前的标准操作流程，每次正式导入前必须逐条检查。
> 导入完成后请将导入结果记录到相关验收文档中。
