## 1. 使用场景

本文档用于以下场景：

- **旧系统正式产品库存数据导入前**：明确旧系统字段与新系统字段的对应关系
- **CSV 导入模板准备**：指导从旧系统导出数据后如何整理 CSV 列名，使导入预览能正确识别
- **字段口径确认**：统一业务团队和技术团队对"库存""库位""分类"等字段含义的理解
- **导入预览规则增强**：为后续 Step 中增强导入预览字段识别规则提供依据
- **正式替换旧系统前人工核对**：作为导入前/导入后人工对账的参照基准

本文档**不替代**：
- 系统操作手册
- 正式上线验收
- 数据库 schema 文档

## 2. 数据来源原则

### 2.1 数据所有权

- **正式产品/库存数据来自旧系统导出文件**，不以当前 V2/V3 内手工录入或测试数据为准
- 旧系统是唯一的"真实业务数据源"，新系统在正式切换前不产生新的业务数据

### 2.2 测试数据处理

- 当前 V2/V3 系统内已有产品、库存、出入库、台账和审计日志均视为**测试业务数据**
- 在导入旧系统真实数据之前，应：
  1. 先完成旧系统字段映射（本文档）
  2. 完成 CSV 导入模板与字段对齐
  3. 通过导入预览验证字段识别正确
  4. 备份当前测试数据（SQLite 备份）
  5. **受控清空**测试业务数据
  6. 再执行正式导入

### 2.3 导入原则

- 导入前必须先备份并受控清空测试业务数据
- 导入后必须进行人工对账（详见第 8 节）
- 不允许绕过预览直接导入
- 导入数据若与旧系统原始数据不一致，以旧系统为准重新导入

## 3. 新系统目标字段

以下为库存自动化管理系统 V2/V3 产品表（`products`）正式导入目标字段。

| # | 字段名 | 中文名称 | 是否必填 | 数据类型 | 示例 | 说明 |
|---|--------|---------|---------|---------|------|------|
| 1 | `sku` | SKU/产品编码 | **必填** | 字符串(≤50) | `"A510301012"` | 产品唯一标识，不可重复，不可为空 |
| 2 | `name` | 产品名称 | **必填** | 字符串(≤100) | `"金牌聚脲清漆"` | 产品中文名称，不可为空 |
| 3 | `category` | 分类 | 强烈推荐 | 字符串(≤50) | `"聚氨酯"` | 库存分类，未填时默认 `"耗材"` |
| 4 | `brand` | 品牌 | 可选 | 字符串(≤100) | `"华元聚合物"` | 品牌/厂牌，允许为空 |
| 5 | `specification` | 规格 | 可选 | 字符串(≤200) | `"S-340"` | 规格/型号，允许为空 |
| 6 | `location` | 存储位置 | 强烈推荐 | 字符串(≤100) | `"A-103"` | 库位/仓位，未填时默认空字符串 |
| 7 | `unit` | 单位 | 强烈推荐 | 字符串(≤20) | `"套"` | 计量单位，未填时默认 `"个"` |
| 8 | `current_stock` | 当前库存 | **必填** | 整数(≥0) | `28` | 本地真实库存数量，必须是非负整数 |
| 9 | `min_stock` | 最低库存 | 可选 | 整数(≥0) | `10` | 安全库存阈值，未填时默认 `0` |
| 10 | `supplier` | 供应商 | 可选 | 字符串(≤100) | `"华元聚合物"` | 供应商/供货商，允许为空 |
| 11 | `notes` | 备注 | 可选 | 文本 | `"2024年新批次"` | 附注说明，允许为空 |
| 12 | `purchase_price` | 采购价 | 可选 | 浮点数(≥0) | `12.50` | 采购单价，允许为空；不为空时须为非负数字 |
| 13 | `sale_price` | 售价 | 可选 | 浮点数(≥0) | `25.00` | 销售单价，允许为空；不为空时须为非负数字 |

> **注意**：
> - `id` 由系统自动生成（格式：`prod-000001`），不需要在 CSV 中提供
> - `status`（库存状态）由系统根据 `current_stock ≤ min_stock` 自动计算，不需要在 CSV 中提供
> - `last_updated` / `updated_at` 由系统自动维护，导入时取当前时间
> - `created_at` 由系统自动生成，不允许外部指定
> - `purchase_price`（采购价）和 `sale_price`（售价）**不参与库存数量计算**，仅作为产品主数据记录。后续可用于库存金额、成本核算、报价参考、报表导出等场景。普通员工是否可见价格字段由权限收口阶段统一处理。

## 5. 必填字段建议

### 5.1 至少必须有（缺一不可）

| 字段 | 原因 |
|------|------|
| **SKU** | 产品唯一标识，缺失则无法区分产品 |
| **产品名称** | 业务基本标识，缺失则无法识别产品 |
| **当前库存** | 库存管理核心数据，缺失则无业务意义 |

这三个字段在导入预览中为**必填**（`REQUIRED_FIELDS`），CSV 缺少任一列会给阻断级 error，`can_import` 会为 `false`。

### 5.2 强烈推荐有

| 字段 | 原因 |
|------|------|
| **分类** | 直接影响库存分类筛选、低库存预警分类统计、仪表盘分类展示 |
| **存储位置** | 实际仓储管理中必不可少，影响库位级别的盘点与查找 |
| **单位** | 避免默认单位"个"不准确，影响出库操作与台账记录 |

未填时系统会使用默认值（分类→`"耗材"`，位置→空，单位→`"个"`），不影响导入，但建议导入前从旧系统整理完整。

### 5.3 允许为空的字段

以下字段允许在旧系统导出时为空，导入后可在系统中人工补充：

| 字段 | 默认值 | 说明 |
|------|--------|------|
| `brand`（品牌） | 空字符串 | 旧系统可能无品牌字段 |
| `specification`（规格） | 空字符串 | 旧系统可能无规格字段 |
| `supplier`（供应商） | 空字符串 | 旧系统可能无供应商字段 |
| `notes`（备注） | 空字符串 | 非必要信息 |
| `min_stock`（最低库存） | `0` | 导入后需人工根据业务规则补齐 |
| `purchase_price`（采购价） | `null`（空） | 价格信息非必填，后续可按需补充 |
| `sale_price`（售价） | `null`（空） | 价格信息非必填，后续可按需补充 |

## 6. 数据校验规则

导入预览阶段（`POST /api/imports/products/preview`）会对 CSV 每一行数据执行以下校验。校验结果不影响预览查看，但会标记行状态（通过/错误/警告），直接影响 `can_import` 判定。

### 6.1 阻断级规则（不通过则 `can_import = false`）

| # | 规则 | 错误码 | 说明 |
|---|------|--------|------|
| E001 | SKU 不应为空 | `E001` | 空 SKU 的行无法创建产品 |
| E002 | SKU 不应重复 | `E002` | CSV 内部 SKU 重复（含与已有数据库产品的 SKU 重复） |
| E003 | 产品名称不应为空 | `E003` | 空名称的行无法创建产品 |
| E004 | 当前库存必须是数字 | `E004` | 无法解析为整数的库存值 |
| E005 | 当前库存不应为负数 | `E005` | 库存为负数不符合物理实际 |
| E006 | 最低库存必须是数字 | `E006` | 无法解析为整数的最低库存 |
| E007 | CSV 编码无法识别 | — | 非 UTF-8 / GBK / GB18030 编码的文件 |
| E008 | 缺少必填列（SKU / 产品名称 / 当前库存） | — | CSV 表头中找不到对应列 |
| E009 | 采购价不是有效数字 | `E009` | 采购价无法解析为数字（如填了文字） |
| E010 | 采购价为负数 | `E010` | 采购价不能为负 |
| E011 | 售价不是有效数字 | `E011` | 售价无法解析为数字（如填了文字） |
| E012 | 售价为负数 | `E012` | 售价不能为负 |

### 6.2 警告级规则（不阻断导入，但建议修正）

| # | 规则 | 警告码 | 说明 |
|---|------|--------|------|
| W001 | 分类为空，将使用默认值"耗材" | `W001` | — |
| W002 | 单位为非标准值 | `W002` | 建议使用标准计量单位 |
| W003 | 存储位置为空 | `W003` | — |
| W004 | 最低库存为 0 | `W004` | 建议导入后根据业务规则人工补齐 |
| W005 | 库存数量异常高（超过阈值） | `W005` | 可能为数据错误，建议人工确认 |
| W006 | 库存列名口径不明确 | `W006` | 列名无法确认是本地真实库存口径，建议确认 |
| W007 | 品牌为空 | `W007` | — |
| W008 | 规格为空 | `W008` | — |
| W009 | 供应商为空 | `W009` | — |
| W010 | 采购价为空 | `W010` | 建议后续补充采购价信息 |
| W011 | 售价为空 | `W011` | 建议后续补充售价信息 |

### 6.3 不阻止导入的情况

- 空品牌、空供应商、空备注、空采购价、空售价**允许存在**，不产生阻断级 error
- 非必填字段（brand / specification / supplier / notes / purchase_price / sale_price / location / unit / min_stock）缺失**不阻止导入**
- 最低库存为 0 或为空（默认 0）**不阻止导入**，但会产生警告，建议导入后人工补齐
- CSV 中存在未被识别的额外列（如旧系统的创建时间、更新人等）**不阻止导入**，会被标记为 `ignored`

## 7. 导入前人工整理建议

在从旧系统导出 CSV 后、提交到新系统导入预览前，建议人工完成以下整理步骤：

### 7.1 列名统一

- [ ] **统一 SKU 列名**：确认旧系统导出 CSV 的 SKU 列名在本系统别名表内（如"产品货号""SKU""货号""编码"等均可识别）
- [ ] **确认库存列口径**：如果旧系统库存列名是泛称（如"库存""总库存"），建议改为"本地库存"或"当前库存"以消除口径警告
- [ ] **分离库存备注**：如果旧系统"备注"列实际包含库存来源等信息，建议拆分为产品备注和库存说明两列

### 7.2 数据清洗

- [ ] **去除明显空行**：删除 CSV 中完全为空的数据行
- [ ] **合并重复产品**：按 SKU 去重，保留最新的库存数据；如同一 SKU 有多行，确认是否需要合并
- [ ] **检查库存数量**：抽查库存数字是否有异常值（如负数、极大值、科学计数法等）
- [ ] **检查库位**：确认库位名称在新系统中有意义（如 "A-103"），避免保留旧系统内部编码
- [ ] **检查分类**：确认旧系统分类能对应到新系统预期的分类口径
- [ ] **检查采购价 / 售价**：确认价格列为纯数字，不含文字或特殊字符；采购价和售价均允许为空

### 7.3 文件管理

- [ ] **保存原始旧系统导出文件**：不要覆盖或修改原始文件，保留为 `.xlsx` 或 `.csv` 存档
- [ ] **另存一份整理后的导入文件**：在原始文件基础上另存为整理后的 CSV（UTF-8 编码推荐，GBK 也可自动识别）
- [ ] **文件位置**：CSV 样本建议放在项目外目录（如 `E:\新建文件夹\2026 AI\旧系统库存导出备份\`），不纳入 Git 版本控制

## 11. 导入预览检查规则

> **本节版本**：v1.0 · 2026-07-01 · Step 10-6B

### 11.1 规则体系概述

导入预览（`POST /api/imports/products/preview`）在执行解析和校验后，按严重程度将问题分为三级：

| 级别 | 标识 | 含义 | 是否阻断导入 |
|------|------|------|-------------|
| **error** | 红色 · 阻断 | 数据存在致命缺陷，无法正确导入 | ✅ 阻断 (`can_import = false`) |
| **warning** | 琥珀色 · 建议 | 数据不完整或有待确认的问题 | ❌ 不阻断，但建议修正 |
| **ignored** | 灰色 · 提示 | 未识别字段，不影响导入 | ❌ 不阻断，仅提示 |

### 11.2 Error 级检查规则（阻断导入）

以下任一条件触发时，`can_import` 为 `false`，前端「执行正式导入」按钮禁用：

| # | 规则 | 检查位置 | 说明 |
|---|------|---------|------|
| E-01 | **缺少必填字段列** | 表头级 | CSV 表头中缺少 `sku`（SKU）、`name`（产品名称）、`current_stock`（当前库存）中任一列。返回 `columns.missing_required` 列表。 |
| E-02 | **SKU 为空** | 行级 | 单行中 SKU 值为空字符串或仅空白字符。 |
| E-03 | **产品名称为空** | 行级 | 单行中产品名称值为空。 |
| E-04 | **当前库存为空** | 行级 | 单行中当前库存值为空。 |
| E-05 | **当前库存不是数字** | 行级 | 当前库存值无法解析为整数（如 `"abc"`、`"12.5"`、`"N/A"`）。 |
| E-06 | **当前库存为负数** | 行级 | 当前库存值为负整数（如 `-5`）。库存为负数不符合物理实际。 |
| E-07 | **CSV 内部 SKU 重复** | 行级 | 同一 CSV 文件中同一 SKU 出现在多行。错误信息中包含所有重复行号。 |
| E-08 | **CSV 编码无法识别** | 文件级 | 文件编码不是 UTF-8 / UTF-8-SIG / GBK / GB18030 之一。 |
| E-09 | **表头重复映射** | 表头级 | 同一规范字段被多个表头同时匹配（如同时存在"SKU"和"产品货号"两列）。 |
| E-10 | **数据行为空** | 文件级 | CSV 仅包含表头行，没有任何数据行。 |

> ⚠️ **注意**：DB 已有 SKU（SKU 已存在于数据库中）**不是 error**。在 `create_only` 模式下，已存在 SKU 会被标记为 warning 并在正式导入时跳过，不会覆盖已有产品数据。

### 11.3 Warning 级检查规则（建议修正，不阻断导入）

#### 11.3.1 必填字段默认值警告（P0 级）

以下字段在 CSV 中为空时，系统会使用默认值填充，但同时产生行级 warning 提示人工确认：

| 字段 | 默认值 | 警告内容 |
|------|--------|---------|
| `category`（分类） | `"耗材"` | 「分类」为空，将使用默认值：耗材 |
| `unit`（单位） | `"个"` | 「单位」为空，将使用默认值：个 |
| `location`（库位） | `""`（空） | 「库位」为空 |
| `min_stock`（最低库存） | `0` | 「最低库存」为空，将使用默认值：0 |

#### 11.3.2 建议填写字段警告（P1 级）

以下字段在 CSV 中为空时，产生行级 warning，但不影响导入：

| 字段 | 警告内容 |
|------|---------|
| `brand`（品牌） | 建议填写「品牌」字段 |
| `specification`（规格） | 建议填写「规格」字段 |
| `supplier`（供应商） | 建议填写「供应商」字段 |
| `notes`（备注） | 建议填写「备注」字段 |

> **注意**：品牌、供应商、备注、规格为空**不能作为 error**，仅产生建议级 warning。

#### 11.3.3 库存口径警告

| 场景 | 级别 | 说明 |
|------|------|------|
| 库存列名使用通用别名（如"库存""总库存"） | 全局 warning | 无法确认是否为本地真实库存口径，提示人工确认 |
| CSV 包含异地/虚拟库存字段 | 全局 warning | 该字段当前系统不保存，不计入本地库存 |
| CSV 包含总可售库存字段 | 全局 warning | 该字段不能替代本地真实库存 |
| 行级当前库存 ≤ 最低库存 | 行级 warning | 导入后将处于「低库存」状态 |
| DB 已有 SKU | 行级 + 全局 warning | 正式导入时将跳过该行，不覆盖已有产品 |
| P1/P2 扩展字段存在 | 全局 warning | 提示哪些字段将写入/不写入数据库 |

### 11.4 CSV 内部重复 SKU 检查

导入预览在解析完所有行后，对 CSV 内部 SKU 执行去重检查：

1. 收集所有行的 SKU 值及其行号
2. 如同一 SKU 在 CSV 中出现 ≥ 2 次，标记为 error（E-07）
3. 错误信息格式：`SKU '{sku}' 在 CSV 内重复出现（行: [3, 7, 12]）`
4. 该错误会同时出现在：
   - 全局错误列表（`errors` 字段）
   - 涉及的各行错误列表（`rows[*].errors`）

> **注意**：此检查仅针对 CSV 内部重复，不检查与数据库已有 SKU 的冲突（那是 warning 而非 error）。

### 11.5 未识别字段处理

CSV 表头中无法匹配到任何已知别名的列，会被标记为 `ignored`：

1. 出现在返回结果的 `columns.ignored` 列表中
2. 前端以灰色删除线样式展示
3. **不报错**，不阻止预览，不阻止导入
4. 这些列的数据不会写入数据库
5. 建议导出 CSV 时清理不需要的列（如采购价、售价、创建时间等）

### 11.6 本轮不执行真实导入

本节（Step 10-6B）仅增强导入预览校验规则和前端展示，**不执行真实导入**：

- ✅ 增强后端校验逻辑（missing_required、P1 空字段 warning）
- ✅ 增强前端字段识别展示（缺失必填字段警示、状态分级提示）
- ✅ 补充文档（本节）
- ❌ 不执行 `POST /api/imports/products/execute`
- ❌ 不清空测试业务数据
- ❌ 不修改任何数据库记录

### 11.7 旧系统无产品货号处理规则（Step 10-6C-fix）

#### 11.7.1 背景

旧系统产品列表中确实存在部分产品没有产品货号（SKU），这是历史业务事实。这些产品仍需迁移到新系统，且以后应能通过产品名称查询。

#### 11.7.2 导入预览处理

在导入预览阶段，系统会对空 SKU 行做以下处理：

| 场景 | 处理方式 | 级别 |
|------|---------|------|
| SKU 为空 + 产品名称存在 | 不报 error，生成迁移 SKU 预览 | warning（可导入） |
| SKU 为空 + 产品名称也为空 | 无法识别产品，报 error | error（阻断） |
| SKU 为非空有效值 | 正常校验 | 按正常规则 |

#### 11.7.3 迁移 SKU 生成规则

对无货号但有产品名称的行：

1. **不修改原始上传文件**，不覆盖 CSV 中的原始空值
2. 预览时生成 `suggested_sku`，格式为 `LEGACY-NOCODE-0001`，编号按 CSV 行顺序稳定递增
3. 行级 warning 提示：`"旧系统产品货号为空，正式导入时将生成迁移 SKU LEGACY-NOCODE-xxxx，产品名称「xxx」保持不变。"`
4. 全局 warning 汇总提示发现多少行无货号产品
5. 正式导入时系统将自动创建产品，以迁移 SKU 作为临时货号
6. **建议后续在系统中为这些产品补充正式的产品货号**

#### 11.7.4 常见空值占位符处理

CSV 中以下值会被统一识别为空 SKU（不生成 "nan" 错误）：

- 空字符串 `""`
- `nan` / `NaN` / `NAN`（pandas/Excel 导出常见占位符）
- `null` / `NULL` / `None` / `nil`
- `NA` / `N/A`
- `-` / `--`

这些值不会产生 "SKU 'nan' 重复" 之类的误导性错误，也不会被加入重复 SKU 检查。

#### 11.7.5 价格字段为空处理

- **采购价为空**：允许，不产生行级 warning，不阻断导入
- **售价为空**：允许，不产生行级 warning，不阻断导入
- **采购价为非数字**：error，阻断导入
- **售价为非数字**：error，阻断导入
- **采购价为负数**：error，阻断导入
- **售价为负数**：error，阻断导入

价格字段的空值不应形成大量行级 warning 刷屏。

#### 11.7.6 P1 字段降噪（品牌/规格/供应商/备注）

- 品牌、规格、供应商、备注为空时**不再产生行级 warning**
- 全局提示中仍会汇总展示识别到的 P1 字段类型
- 避免大量黄色 warning 刷屏导致真正的阻断错误难以识别
