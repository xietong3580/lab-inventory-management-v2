# 旧系统正式数据导入字段映射表

> **文档版本**：v1.0
> **创建日期**：2026-07-01
> **适用范围**：库存自动化管理系统 V2/V3
> **前置步骤**：Step 10-6A

---

## 1. 使用场景

本文档用于以下场景：

- **旧系统正式产品库存数据导入前**：明确旧系统字段与新系统字段的对应关系
- **CSV 导入模板准备**：指导从旧系统导出数据后如何整理 CSV 列名，使导入预览能正确识别
- **字段口径确认**：统一业务团队和技术团队对"库存""库位""分类"等字段含义的理解
- **导入预览规则增强**：为后续 Step 中增强导入预览字段识别规则提供依据
- **正式替换旧系统前人工核对**：作为导入前/导入后人工对账的参照基准

本文档**不替代**：
- 系统操作手册
- 正式上线验收
- 数据库 schema 文档

## 2. 数据来源原则

### 2.1 数据所有权

- **正式产品/库存数据来自旧系统导出文件**，不以当前 V2/V3 内手工录入或测试数据为准
- 旧系统是唯一的"真实业务数据源"，新系统在正式切换前不产生新的业务数据

### 2.2 测试数据处理

- 当前 V2/V3 系统内已有产品、库存、出入库、台账和审计日志均视为**测试业务数据**
- 在导入旧系统真实数据之前，应：
  1. 先完成旧系统字段映射（本文档）
  2. 完成 CSV 导入模板与字段对齐
  3. 通过导入预览验证字段识别正确
  4. 备份当前测试数据（SQLite 备份）
  5. **受控清空**测试业务数据
  6. 再执行正式导入

### 2.3 导入原则

- 导入前必须先备份并受控清空测试业务数据
- 导入后必须进行人工对账（详见第 8 节）
- 不允许绕过预览直接导入
- 导入数据若与旧系统原始数据不一致，以旧系统为准重新导入

## 3. 新系统目标字段

以下为库存自动化管理系统 V2/V3 产品表（`products`）正式导入目标字段。

| # | 字段名 | 中文名称 | 是否必填 | 数据类型 | 示例 | 说明 |
|---|--------|---------|---------|---------|------|------|
| 1 | `sku` | SKU/产品编码 | **必填** | 字符串(≤50) | `"A510301012"` | 产品唯一标识，不可重复，不可为空 |
| 2 | `name` | 产品名称 | **必填** | 字符串(≤100) | `"金牌聚脲清漆"` | 产品中文名称，不可为空 |
| 3 | `category` | 分类 | 强烈推荐 | 字符串(≤50) | `"聚氨酯"` | 库存分类，未填时默认 `"耗材"` |
| 4 | `brand` | 品牌 | 可选 | 字符串(≤100) | `"华元聚合物"` | 品牌/厂牌，允许为空 |
| 5 | `specification` | 规格 | 可选 | 字符串(≤200) | `"S-340"` | 规格/型号，允许为空 |
| 6 | `location` | 存储位置 | 强烈推荐 | 字符串(≤100) | `"A-103"` | 库位/仓位，未填时默认空字符串 |
| 7 | `unit` | 单位 | 强烈推荐 | 字符串(≤20) | `"套"` | 计量单位，未填时默认 `"个"` |
| 8 | `current_stock` | 当前库存 | **必填** | 整数(≥0) | `28` | 本地真实库存数量，必须是非负整数 |
| 9 | `min_stock` | 最低库存 | 可选 | 整数(≥0) | `10` | 安全库存阈值，未填时默认 `0` |
| 10 | `supplier` | 供应商 | 可选 | 字符串(≤100) | `"华元聚合物"` | 供应商/供货商，允许为空 |
| 11 | `notes` | 备注 | 可选 | 文本 | `"2024年新批次"` | 附注说明，允许为空 |

> **注意**：
> - `id` 由系统自动生成（格式：`prod-000001`），不需要在 CSV 中提供
> - `status`（库存状态）由系统根据 `current_stock ≤ min_stock` 自动计算，不需要在 CSV 中提供
> - `last_updated` / `updated_at` 由系统自动维护，导入时取当前时间
> - `created_at` 由系统自动生成，不允许外部指定

## 5. 必填字段建议

### 5.1 至少必须有（缺一不可）

| 字段 | 原因 |
|------|------|
| **SKU** | 产品唯一标识，缺失则无法区分产品 |
| **产品名称** | 业务基本标识，缺失则无法识别产品 |
| **当前库存** | 库存管理核心数据，缺失则无业务意义 |

这三个字段在导入预览中为**必填**（`REQUIRED_FIELDS`），CSV 缺少任一列会给阻断级 error，`can_import` 会为 `false`。

### 5.2 强烈推荐有

| 字段 | 原因 |
|------|------|
| **分类** | 直接影响库存分类筛选、低库存预警分类统计、仪表盘分类展示 |
| **存储位置** | 实际仓储管理中必不可少，影响库位级别的盘点与查找 |
| **单位** | 避免默认单位"个"不准确，影响出库操作与台账记录 |

未填时系统会使用默认值（分类→`"耗材"`，位置→空，单位→`"个"`），不影响导入，但建议导入前从旧系统整理完整。

### 5.3 允许为空的字段

以下字段允许在旧系统导出时为空，导入后可在系统中人工补充：

| 字段 | 默认值 | 说明 |
|------|--------|------|
| `brand`（品牌） | 空字符串 | 旧系统可能无品牌字段 |
| `specification`（规格） | 空字符串 | 旧系统可能无规格字段 |
| `supplier`（供应商） | 空字符串 | 旧系统可能无供应商字段 |
| `notes`（备注） | 空字符串 | 非必要信息 |
| `min_stock`（最低库存） | `0` | 导入后需人工根据业务规则补齐 |

## 6. 数据校验规则

导入预览阶段（`POST /api/imports/products/preview`）会对 CSV 每一行数据执行以下校验。校验结果不影响预览查看，但会标记行状态（通过/错误/警告），直接影响 `can_import` 判定。

### 6.1 阻断级规则（不通过则 `can_import = false`）

| # | 规则 | 错误码 | 说明 |
|---|------|--------|------|
| E001 | SKU 不应为空 | `E001` | 空 SKU 的行无法创建产品 |
| E002 | SKU 不应重复 | `E002` | CSV 内部 SKU 重复（含与已有数据库产品的 SKU 重复） |
| E003 | 产品名称不应为空 | `E003` | 空名称的行无法创建产品 |
| E004 | 当前库存必须是数字 | `E004` | 无法解析为整数的库存值 |
| E005 | 当前库存不应为负数 | `E005` | 库存为负数不符合物理实际 |
| E006 | 最低库存必须是数字 | `E006` | 无法解析为整数的最低库存 |
| E007 | CSV 编码无法识别 | — | 非 UTF-8 / GBK / GB18030 编码的文件 |
| E008 | 缺少必填列（SKU / 产品名称 / 当前库存） | — | CSV 表头中找不到对应列 |

### 6.2 警告级规则（不阻断导入，但建议修正）

| # | 规则 | 警告码 | 说明 |
|---|------|--------|------|
| W001 | 分类为空，将使用默认值"耗材" | `W001` | — |
| W002 | 单位为非标准值 | `W002` | 建议使用标准计量单位 |
| W003 | 存储位置为空 | `W003` | — |
| W004 | 最低库存为 0 | `W004` | 建议导入后根据业务规则人工补齐 |
| W005 | 库存数量异常高（超过阈值） | `W005` | 可能为数据错误，建议人工确认 |
| W006 | 库存列名口径不明确 | `W006` | 列名无法确认是本地真实库存口径，建议确认 |
| W007 | 品牌为空 | `W007` | — |
| W008 | 规格为空 | `W008` | — |
| W009 | 供应商为空 | `W009` | — |

### 6.3 不阻止导入的情况

- 空品牌、空供应商、空备注**允许存在**，不产生阻断级 error
- 非必填字段（brand / specification / supplier / notes / location / unit / min_stock）缺失**不阻止导入**
- 最低库存为 0 或为空（默认 0）**不阻止导入**，但会产生警告，建议导入后人工补齐
- CSV 中存在未被识别的额外列（如旧系统的采购价、售价、创建时间等）**不阻止导入**，会被标记为 `ignored`

## 7. 导入前人工整理建议

在从旧系统导出 CSV 后、提交到新系统导入预览前，建议人工完成以下整理步骤：

### 7.1 列名统一

- [ ] **统一 SKU 列名**：确认旧系统导出 CSV 的 SKU 列名在本系统别名表内（如"产品货号""SKU""货号""编码"等均可识别）
- [ ] **确认库存列口径**：如果旧系统库存列名是泛称（如"库存""总库存"），建议改为"本地库存"或"当前库存"以消除口径警告
- [ ] **分离库存备注**：如果旧系统"备注"列实际包含库存来源等信息，建议拆分为产品备注和库存说明两列

### 7.2 数据清洗

- [ ] **去除明显空行**：删除 CSV 中完全为空的数据行
- [ ] **合并重复产品**：按 SKU 去重，保留最新的库存数据；如同一 SKU 有多行，确认是否需要合并
- [ ] **检查库存数量**：抽查库存数字是否有异常值（如负数、极大值、科学计数法等）
- [ ] **检查库位**：确认库位名称在新系统中有意义（如 "A-103"），避免保留旧系统内部编码
- [ ] **检查分类**：确认旧系统分类能对应到新系统预期的分类口径

### 7.3 文件管理

- [ ] **保存原始旧系统导出文件**：不要覆盖或修改原始文件，保留为 `.xlsx` 或 `.csv` 存档
- [ ] **另存一份整理后的导入文件**：在原始文件基础上另存为整理后的 CSV（UTF-8 编码推荐，GBK 也可自动识别）
- [ ] **文件位置**：CSV 样本建议放在项目外目录（如 `E:\新建文件夹\2026 AI\旧系统库存导出备份\`），不纳入 Git 版本控制

## 8. 导入后人工对账

正式导入完成后，必须进行以下人工对账检查：

### 8.1 总量核对

| 检查项 | 方法 | 通过标准 |
|--------|------|---------|
| 产品总数 | 对比旧系统导出文件行数与新系统产品列表总数 | 一致（扣除被跳过 SKU 后） |
| SKU 总数 | 对比旧系统导出 SKU 去重数 | 一致 |
| 当前库存总量 | 对比旧系统导出库存总和 | 一致 |
| 低库存数量 | 对比旧系统低于预警线的产品数 | 大致一致（取决于 min_stock 是否已补齐） |

### 8.2 抽查核对

| 检查项 | 方法 | 通过标准 |
|--------|------|---------|
| 抽查 20 个产品 | 在新系统中随机查看 20 个产品的 SKU/名称/库存/分类 | 与旧系统原始数据一致 |
| 抽查重点库位 | 在旧系统中挑 3-5 个库存较大的库位，在新系统中按库位筛选 | 产品数/库存量一致 |
| 抽查品牌/规格 | 在旧系统中挑有品牌和规格的产品，在新系统中确认 | 品牌/规格正确写入 |
