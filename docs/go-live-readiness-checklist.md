# 管理员维护检查清单

> 版本：V2/V3 Step 10-8A
> 更新时间：2026-07-03
> 适用范围：管理员在正式启用、清空数据、批量录入、备份恢复等重要操作前的安全检查

---

## 1. 维护操作总原则

1. **安全第一** — 操作前先备份，操作后核对
2. **人工确认** — 产品数据以人工逐个核对为准，不盲目信任批量数据
3. **可回滚** — 确保有可用备份再执行任何可能破坏数据的操作
4. **可追溯** — 所有关键操作记录在审计日志中

---

## 2. 手动录入正式产品路线

用户最终决定：正式产品主数据不走批量正式导入主路线，而是由用户逐个手动录入，以保证准确性。

- 旧系统 CSV / 腾讯共享文档仅作为参考底稿和核对资料
- 已有导入预览功能继续保留，作为辅助检查工具
- 旧系统历史出入库记录后续做只读归档，不参与当前库存计算

---

## 3. 维护操作步骤

### 第一步：创建数据库备份
在设置页面点击「创建数据库备份」，确保操作前有可回滚节点。

### 第二步：确认当前数据状态
- 访问设置页面的「管理员维护检查」模块
- 查看产品、出入库记录、审计日志等数据概览
- 判断当前数据是否为正式数据

### 第三步：处理现有数据
- 如当前数据并非正式数据，先创建备份
- 再通过设置页面「清空测试业务数据」功能处理

### 第四步：分批录入正式产品
- 按库存分类或库位分批录入
- 利用「保存并继续新增」提高效率
- 每批录入后导出 CSV 与旧系统/腾讯文档反向核对

### 第五步：核对检查
- 产品数量是否一致
- 产品名称是否准确
- SKU 编码是否唯一正确
- 库存数量是否与实物相符
- 库位分配是否正确

### 第六步：创建正式录入后备份
全部产品录入并核对完成后，再次创建数据库备份。

### 第七步：确认系统状态
- 管理员维护检查模块显示状态为"ok"或"warning"
- 无负库存
- 无重复 SKU
- 有可用备份

### 第八步：正式开始使用
开始正式出入库操作。

---

## 4. 录入注意事项

### 采购价/售价
- 未知时留空，不要填 0
- 0 表示免费/零价格
- 留空表示未知
- 后续可通过编辑补充

### 无货号产品
- 使用内部编号如 LEGACY-NOCODE-0001
- 产品名称保持真实
- 便于后续识别和管理

### 当前库存
- 必须人工确认后录入
- 不要直接照搬旧系统库存数字
- 如有差异，以实物为准

---

## 5. 备份策略建议

| 阶段 | 建议 |
|------|------|
| 录入前 | 创建初始备份 |
| 每批录入后 | 创建备份 + 导出 CSV 核对 |
| 全部录入后 | 创建数据库备份 |
| 日常运维 | 每天创建 1 次备份 |
| 重要操作前 | 操作前立即创建备份 |

---

## 6. 日常运维

### 第一周
- 每天创建数据库备份
- 每天导出 CSV 核对当天新增数据
- 关注低库存预警

### 日常运维
- 定期查看审计日志
- 定期运行恢复预检确认备份可用
- 定期清理过旧备份

### 出问题时
1. 先看审计日志，确认最近操作
2. 运行恢复预检，确认备份可用
3. 查看恢复准备计划
4. 如果需要恢复，按恢复流程执行（当前版本需管理员操作）
5. 不要直接手工修改数据库文件

---

## 7. 禁止事项

- ❌ 未创建备份时执行清空操作
- ❌ 把未知价格填为 0
- ❌ 混入旧系统历史出入库记录
- ❌ 未核对库存数量前直接启用
- ❌ 直接手工修改数据库文件
- ❌ 提交数据库/备份文件到 Git 仓库
- ❌ 出问题时盲目修改数据
