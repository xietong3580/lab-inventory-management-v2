### 3.1 字段总览

| A | **SKU** | `sku` | `sku` | String | ✅ 必填 | — | 50 |
| B | **产品名称** | `name` | `name` | String | ✅ 必填 | — | 100 |
| C | **分类** | `category` | `category` | String | ❌ | `耗材` | 50 |

### 3.2 字段详解

#### A. SKU（必填）

| 属性 | 值 |
|------|-----|
| CSV 表头 | `SKU` |
| 数据库映射 | `Product.sku` |
| 类型 | 字符串 |
| 最大长度 | 50 字符 |
| 必填 | ✅ 是 |
| 唯一性 | ✅ 必须唯一（全局，含数据库已有 SKU） |
| 空白处理 | 前后去空格（`.trim()`） |
| 校验规则 | 不能为空、不能仅含空白、不能包含 CSV 分隔符冲突字符（如逗号需转义） |

**旧系统迁移注意**：
- 旧系统可能使用纯数字 SKU（如 `000123`），导入时保留原值
- 旧系统可能没有 SKU 字段（仅靠物料编码），需提前用物料编码填充 SKU 列
- 如果旧系统 SKU 含特殊字符（如中文、空格），保留原值但建议在导入报告中标注

#### B. 产品名称（必填）

| 属性 | 值 |
|------|-----|
| CSV 表头 | `产品名称` |
| 数据库映射 | `Product.name` |
| 类型 | 字符串 |
| 最大长度 | 100 字符 |
| 必填 | ✅ 是 |
| 校验规则 | 不能为空、不能仅含空白、超长截断并警告 |

**旧系统迁移注意**：
- 旧系统产品名称可能包含规格型号信息（如"钨钢铣刀 D6×50 3刃"），保留原值
- 名称超过 100 字符的，建议手动缩短后导入，或在导入报告中标注截断

#### C. 分类（可选）

| 属性 | 值 |
|------|-----|
| CSV 表头 | `分类` |
| 数据库映射 | `Product.category` |
| 类型 | 字符串 |
| 最大长度 | 50 字符 |
| 必填 | ❌ 否 |
| 默认值 | `耗材` |
| 已知有效值 | `耗材`、`试剂`、`设备` |
| 校验规则 | 空值时使用默认值；不在已知列表中的值**警告**（不阻断） |

**旧系统迁移注意**：
- 旧系统分类名可能完全不同（如"刀具"、"量具"、"防护"等），导入时保留原名
- 建议在导入前做分类映射：将旧分类统一映射到新系统的 3 个分类之一
- 如果选择保留旧分类名，后续可在产品管理页编辑

#### D. 当前库存（可选）

| 属性 | 值 |
|------|-----|
| CSV 表头 | `当前库存` |
| 数据库映射 | `Product.current_stock` |
| 类型 | 整数 |
| 必填 | ❌ 否 |
| 默认值 | `0` |
| 校验规则 | 必须为非负整数（≥ 0），不接受小数、负数、非数字值 |

**关键规则**：
- `current_stock` 作为**期初库存**导入，不生成历史出入库记录
- 导入报告中标注"期初库存数据"，区分于日常出入库
- 后续如需记录"期初库存"来源，可在 Step 9-9 单独处理（如生成一条类型为"期初"的特殊交易记录）
- 库存为 0 是合法值（表示该产品当前无库存）

**旧系统迁移注意**：
- 旧系统可能有小数库存（如 1.5 瓶），需提前决定策略：向下取整 / 四舍五入 / 保留小数（需改模型）
- 当前模型 `current_stock` 为 Integer，小数库存需预处理为整数
- 如果旧系统有预占库存、在途库存等概念，当前模型不支持，需单独记录

#### E. 最低库存（可选）

| 属性 | 值 |
|------|-----|
| CSV 表头 | `最低库存` |
| 数据库映射 | `Product.min_stock` |
| 类型 | 整数 |
| 必填 | ❌ 否 |
| 默认值 | `0` |
| 校验规则 | 必须为非负整数（≥ 0） |

**与 current_stock 的关系**：
- `min_stock = 0` 表示不设最低库存阈值（永远不会触发低库存预警）
- `min_stock > 0` 且 `current_stock <= min_stock` → 系统自动标记为"低库存"
- 如果设置了 `min_stock` 但忘记设置 `current_stock`（默认 0），产品将立即显示为"低库存"

**旧系统迁移注意**：
- 旧系统可能没有最低库存字段，导入时使用默认值 0
- 建议迁移后根据实际业务需求逐产品设置合理的最低库存阈值

#### F. 单位（可选）

| 属性 | 值 |
|------|-----|
| CSV 表头 | `单位` |
| 数据库映射 | `Product.unit` |
| 类型 | 字符串 |
| 最大长度 | 20 字符 |
| 必填 | ❌ 否 |
| 默认值 | `个` |

**常见单位值**：个、支、瓶、盒、箱、包、卷、桶、套、台、kg、g、L、mL、m

**旧系统迁移注意**：
- 旧系统单位命名可能不统一（如"个" vs "PCS"、"支" vs "PC"），建议提前统一
- 单位超长（>20 字符）的截断并警告

#### G. 存储位置（可选）

| 属性 | 值 |
|------|-----|
| CSV 表头 | `存储位置` |
| 数据库映射 | `Product.location` |
| 类型 | 字符串 |
| 最大长度 | 100 字符 |
| 必填 | ❌ 否 |
| 默认值 | 空字符串 |
| 校验规则 | 可为空，超长截断并警告 |

**旧系统迁移注意**：
- 旧系统位置编码可能格式各异（如"A-3-2"、"仓库1-货架B"、"R1-S2-L3"）
- 如果旧系统有仓库/库位两级结构，当前模型仅支持单一 location 字段，建议合并存储

## 7. 重复产品处理规则

### 7.1 重复检测维度

- **唯一键**：`sku`（数据库级别 UNIQUE 约束）
- 检测范围：CSV 文件内部 + CSV vs 数据库已有数据
- 不按名称检测重复（同名不同 SKU 视为不同产品）

### 7.2 重复处理策略

第一版（Step 9-3 ~ 9-5）仅支持以下策略：

| 策略 | 编码 | 行为 | 默认 |
|------|------|------|------|
| **报错跳过** | `skip` | SKU 冲突的行标记为 E004 错误，不导入，其他行正常导入 | ✅ 默认 |
| **严格报错** | `strict` | 任意一个 SKU 冲突即中止整个导入（零行导入） | |

后续版本可扩展：

| 策略 | 编码 | 行为 | 适用场景 |
|------|------|------|---------|
| **更新覆盖** | `update` | 更新已有产品的名称、分类、单位、位置、最低库存（**不更新库存数量**） | 数据修正 |
| **库存覆盖** | `overwrite` | 更新已有产品的所有字段（**含库存数量**） | 库存盘点后全量同步 |

**第一版默认行为**：预览阶段对重复 SKU 报 `E004` 错误，该行不导入，其他行正常处理。导入报告中明确列出被跳过的行及原因。

### 7.3 去重决策树

```
CSV 行中的 SKU
    │
    ├── 为空 → E001（阻断）
    │
    ├── 在 CSV 文件中重复 → E003（阻断）
    │
    ├── 在数据库中已存在
    │       │
    │       └── 策略 = skip（默认） → E004（该行跳过，其他行正常）
    │       └── 策略 = strict → E004（全部中止）
    │
    └── 唯一 → ✅ 通过
```

## 8. 当前库存导入规则

### 8.1 基本规则

- `current_stock` 作为**初始库存（期初库存）**直接写入 `products.current_stock`
- **不自动生成出入库历史记录**（出入库台账不包含导入操作）
- 导入完成后写入审计日志：`IMPORT_PRODUCTS`，记录导入行数和文件名
- `last_updated` 自动设置为导入当天的日期（`YYYY-MM-DD`）

### 8.2 是否生成"期初库存"交易记录

**第一版建议：不生成。** 原因：
- 期初库存不是一次真实的出入库操作
- 生成虚拟交易记录会污染出入库历史
- 如果未来需要追溯，可以在产品详情页或审计日志中查看导入记录

**后续可选方案**（不包含在本轮）：
- 为每个导入的产品生成一条 `type = "期初"` 或 `type = "库存初始化"` 的交易记录
- 在导入报告中单独列出期初库存汇总
- 在 product 详情页增加"数据来源"字段标明迁移来源

### 8.3 导入后的库存状态

导入完成后，系统按标准规则自动计算 `status`：
- `current_stock > min_stock` → "正常"
- `current_stock <= min_stock` → "低库存"

导入报告中汇总：
- 正常库存产品数
- 低库存产品数（含零库存）
- 零库存产品数（`current_stock = 0`）

## 9. 校验错误分类汇总

### 9.1 校验结果结构

```
总行数（不含表头）:      N
├── ✅ 可导入:          n_pass     （无任何错误）
├── ⚠️ 警告:           n_warn     （有警告但可导入）
├── ❌ 错误:           n_error    （有阻断错误，不可导入）
│   ├── E001 空 SKU:           x 行
│   ├── E003 重复 SKU:         x 行
│   ├── E004 SKU 已存在:       x 行
│   ├── E005 空名称:           x 行
│   └── ...
└── ⏭️ 跳过（因错误）: n_skip     （有阻断错误的行不会导入）
```

### 9.2 错误展示等级

| 等级 | 图标 | 含义 | 用户操作 |
|------|------|------|---------|
| 阻断 | ❌ | 有错误行，必须修正后重新上传 | 下载错误报告 → 修正 CSV → 重新上传 |
| 警告 | ⚠️ | 可导入但建议人工复核 | 查看警告列表 → 决定是否继续导入 |
| 通过 | ✅ | 全部通过，可直接导入 | 点击确认导入 |

## 11. 导入前自动备份要求

### 11.1 强制备份

导入执行前**必须**自动创建数据库备份，此步骤不可跳过：

1. 用户点击"确认导入"
2. 前端调用 `POST /api/backups/manual` → 创建备份
3. 备份成功 → 继续执行导入
4. 备份失败 → **禁止导入**，展示错误信息："导入前自动备份失败，已取消导入操作。请检查磁盘空间或数据库状态后重试。"

## 12. 导入后验收

### 12.1 自动验收检查

导入完成后自动输出验收摘要：

| 验收项 | 检查方法 | 通过标准 |
|--------|---------|---------|
| 产品总数 | `SELECT COUNT(*) FROM products` | 原有产品数 + 成功导入数 = 当前产品数 |
| SKU 唯一性 | `SELECT sku, COUNT(*) FROM products GROUP BY sku HAVING COUNT(*) > 1` | 无结果 |
| 库存总量 | `SELECT SUM(current_stock) FROM products WHERE ...` | 导入前后库存量一致 |
| 低库存数 | `SELECT COUNT(*) FROM products WHERE current_stock <= min_stock` | 与预览结果一致 |
| 备份文件 | 检查文件存在 + `PRAGMA integrity_check` | 文件存在且校验通过 |

### 12.2 人工抽查建议

导入后建议人工抽查：
- 随机抽取 5-10 个产品，检查字段是否与 CSV 一致
- 重点抽查库存数量较大或为 0 的产品
- 抽查分类非常见值的产品

## 附录 A：CSV 格式技术规范

### A.1 编码

- **编码**：UTF-8 with BOM（`﻿`），与当前导出保持一致
- **换行符**：`\n`（LF）或 `\r\n`（CRLF）均可接受
- **分隔符**：逗号（`,`）
- **引号**：字段值含逗号、换行符或双引号时，用双引号包裹，内部双引号加倍转义（`""`）

### A.2 表头行

- CSV 文件**第一行必须是表头**
- 表头按本文档第 4 节映射表解析
- 表头列顺序**不要求固定**，系统按表头名称匹配列
- 未知表头列被忽略

### A.3 空白行

- 完全空白的行被跳过（不报错）
- 仅含空白字符的行被跳过
