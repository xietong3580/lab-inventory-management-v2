# Step 10-1B 真实旧系统样本 CSV 准备指南

> **编写日期**：2026-06-28
> **编写性质**：样本准备指南，不修改任何功能代码，不执行任何导入操作
> **前置条件**：Step 9-5E 正式导入链路已闭环，Step 10-1A 验收准备文档已完成

---

## 一、背景

当前产品 CSV 导入链路已完成阶段性闭环：

```
上传 CSV → 预览校验 → 二次确认 → 备份确认 → 正式写库 → 结果展示 → Products 可见 → AuditLog 可追溯
```

Step 10-1A 已梳理字段映射、验收流程、风险点和通过标准。下一步需要实际准备旧系统真实导出的少量产品数据进行小批量迁移验收。

本指南的目的是：**在安全、干净、不污染 Git 仓库的前提下**，指导用户完成样本准备。

---

## 二、本轮目标

1. 准备 10~30 条真实旧系统产品样本
2. 覆盖不同库存状态、分类、单位、品牌、供应商、库位和备注
3. 验证旧系统字段是否能被新系统导入识别
4. **防止真实 CSV 被误提交到 Git**
5. 为 Step 10-1C 预览验收做准备

本轮不执行任何导入操作，不修改任何功能代码。

---

## 三、安全原则

> ⚠️ 以下原则为强制要求，不可协商。

| # | 原则 | 原因 |
|---|------|------|
| 1 | **真实旧系统 CSV 是业务数据，不是开发文件** | 包含真实产品库存信息，属于内部数据 |
| 2 | **不要提交到 Git** | 一旦提交，删除困难，且可能在 push 后暴露到远程仓库 |
| 3 | **不要放进 docs/** | docs 目录内的文件通常会被一起提交 |
| 4 | **不要发到公开仓库** | 即使脱敏，也不应出现在公开仓库中 |
| 5 | **只放在本地忽略目录** | `.local-import-samples/` 已被 .gitignore 忽略 |
| 6 | **导入前先备份数据库** | 防止误操作导致数据丢失 |
| 7 | **用副本 CSV 测试** | 不直接操作旧系统原始导出文件 |
| 8 | **不直接在旧系统执行导出测试** | 导出是只读操作，不影响旧系统 |

## 四、本地目录规范

### 4.1 目录结构

已创建本地忽略目录：

```

```


示例：

```
legacy-products-sample-20260628.csv
legacy-products-sample-20260628-notes.md
```

### 4.3 .gitignore 保护

`.gitignore` 已追加以下规则：

```gitignore
# Local-only CSV import samples; never commit real legacy inventory exports
.local-import-samples/
private-import-samples/
local-import-samples/
```

这三个目录中的任何文件都不会被 Git 跟踪，确保了真实业务数据的安全。

### 4.4 安全验证

每次操作前请确认：

```bash
# 确认目录存在
ls .local-import-samples/

# 确认 git 不跟踪该目录
git status --short

# 如果 git status 显示 .csv 文件，立即停止，不要提交
```

## 五、旧系统样本选择规则

### 5.1 建议选 10~30 条，覆盖以下维度

| # | 维度 | 具体覆盖 | 建议数量 | 验证点 |
|---|------|----------|----------|--------|
| 1 | 库存状态 | 正常库存（库存 > 最低库存） | 3~5 | 状态计算正确 |
| 2 | 库存状态 | 低库存（库存 ≤ 最低库存） | 2~3 | 低库存标签正确 |
| 3 | 库存状态 | 库存为 0 | 2~3 | 零库存边界处理 |
| 4 | 分类 | 至少 2~3 个不同分类 | 3~5 | 分类字段映射 |
| 5 | 单位 | 瓶/盒/支/套/个等不同单位 | 3~5 | 单位字段映射 |
| 6 | 品牌 | 有品牌字段的产品 | 2~3 | P1 可选字段 |
| 7 | 供应商 | 有供应商字段的产品 | 2~3 | P1 可选字段 |
| 8 | 库位 | 有库位字段的产品 | 2~3 | P1 可选字段 |
| 9 | 备注 | 有备注字段的产品 | 2~3 | P2 字段映射 |
| 10 | SKU 格式 | 纯数字 / 纯字母 / 混合 / 短SKU / 长SKU / 带横杠 | 3~5 | SKU 解析准确 |
| 11 | 产品名称 | 纯中文 / 含英文型号 / 含特殊字符 | 3~5 | 名称不乱码 |
| 12 | 重叠 SKU | 可能与新系统已有数据重复的 SKU | 1~2 | skipped 行为验证 |
| 13 | 库存口径 | 有总库存 / 可售库存 / 异地库存的产品 | 1~3 | 库存口径不合并 |

**建议样本总数**：10~30 条

### 5.2 特别提醒

- 一条样本可以同时覆盖多个维度（如：一条低库存 + 有供应商 + 有品牌 + 有库位的产品）
- 如果旧系统没有某些字段（如没有 min_stock），需要在 CSV 中手工添加该列并填入合理值
- 如果旧系统某些字段名称与新系统不一致，先不要改名，记录在 notes.md 中，后续考虑字段别名映射

## 六、不要选择的样本

### 6.1 暂时不要选择

| # | 不要选择 | 原因 |
|---|----------|------|
| 1 | 大批量全量数据（100+） | 先小批量验证，不要一次导入太多 |
| 2 | 明显脏数据特别多的产品 | 先选干净数据验证基本链路 |
| 3 | 含供应商敏感价格的产品 | 价格字段不需要导入，应删除 |
| 4 | 含客户名称的产品 | 客户信息不需要导入 |
| 5 | 含采购价/成本价的产品 | 成本敏感信息应脱敏 |
| 6 | 含内部备注有隐私信息的产品 | 涉及个人信息 |
| 7 | 不确定来源的数据 | 来源不明的数据存在安全和合规风险 |
| 8 | 与旧系统正常业务无关的测试数据 | 无法验证真实兼容性 |

### 6.2 处理建议

如果旧系统导出的 CSV 包含以上敏感字段：
1. 在副本 CSV 中**整列删除**
2. 或在副本 CSV 中将敏感单元格内容替换为 `[已脱敏]`
3. 不要依赖"系统会自动忽略"来保护敏感数据

## 七、建议保留字段

### 7.1 保留用于导入验证

| 字段 | 用途 | 备注 |
|------|------|------|
| SKU | P0 必填，产品唯一标识 | 不能为空 |
| 产品名称 | P0 必填 | 不能为空 |
| 分类 | P0 必填 | 可为空？检查阻断行为 |
| 单位 | P0 必填 | 瓶/盒/支等 |
| 当前库存（本地库存） | P0 必填，写入 current_stock | 必须是合法数字 |
| 最低库存 | P0 必填，写入 min_stock | 必须是合法数字 |
| 库位 / 存储位置 | P1 可选，写入 location | 有则写，无则留空 |
| 品牌 | P1 可选，写入 brand | 有则写 |
| 供应商 | P1 可选，写入 supplier | 有则写 |
| 规格 | P1 可选 | 如果有，可保留验证 |
| 备注 | P2 可选，写入 stock_note | 参考用途 |
| 异地库存 | STOCK_CONTEXT 仅预览 | 验证不写入 current_stock |
| 虚拟库存 | STOCK_CONTEXT 仅预览 | 验证不写入 current_stock |
| 总库存（可售库存） | STOCK_CONTEXT 仅预览 | 验证不写入 current_stock |

### 7.2 说明

- **异地库存、虚拟库存、总库存**只用于验证系统是否正确将其识别为"库存口径参考字段"
- 这些字段**不写入 current_stock**，不会被合并到产品库存中
- 如果旧系统没有这些字段，无需强行添加

| 11 | 员工姓名 | **整列删除** |

## 九、准备步骤

### 用户操作步骤

```
Step 1：从旧系统导出产品 CSV
  → 选择导出范围（10~30 条产品）
  → 尽量选择 UTF-8 编码导出，如只能 GBK 也保留原始编码
  → 将导出文件保存到本地磁盘（不要直接放入项目目录）

Step 2：复制一份副本
  → 复制导出文件，不要直接操作原始导出文件
  → 副本文件名：legacy-products-sample-YYYYMMDD.csv

Step 3：筛选代表性数据
  → 从副本中筛选 10~30 条代表性数据
  → 参考"五、旧系统样本选择规则"
  → 覆盖正常库存、低库存、零库存、不同分类、不同单位等

Step 4：删除或脱敏敏感字段
  → 参考"八、建议删除或脱敏的字段"
  → 在副本 CSV 中直接删除敏感列
  → 必要时替换敏感单元格为 [已脱敏]

Step 5：检查和补充必要字段
  → 确保有 SKU、产品名、current_stock（或等效字段）、min_stock、分类、单位
  → 如果旧系统没有 min_stock 列，手工添加并填写合理值
  → 如果旧系统列名不同于新系统，先记录在 notes.md，暂时不要改列名

Step 6：保存文件
  → 编码：如果原始为 GBK，建议用 VSCode 另存为 UTF-8 测试
  → 也可保留 GBK 副本用于对比测试
  → 文件命名：legacy-products-sample-YYYYMMDD.csv

Step 7：放入安全目录
  → 将 CSV 文件放入 .local-import-samples/ 目录
  → 确认 .local-import-samples/ 已在 .gitignore 中

Step 8：Git 安全检查
  → 执行 git status --short
  → 确认 .csv 文件不出现在未跟踪列表中
  → 如果出现，说明 .gitignore 未生效，停止操作

Step 9：预览验收
  → 进入产品 CSV 导入预览页
  → 仅先做预览，不执行导入
  → 记录字段识别结果
  → 记录 errors / warnings

Step 10（可选，谨慎操作）：正式导入
  → 预览通过且无误后
  → 先备份数据库
  → 二次确认勾选"已备份数据库"
  → 执行正式导入
```

|------|-----|--------|----------|----------|----------|------|----------|

### 问题类型说明

| 问题类型 | 是否阻断导入 | 说明 |
|----------|-------------|------|

## 十二、Git 安全检查

### 12.1 每次 commit 前必须执行

```bash
# 检查工作区状态
git status --short

# 检查是否有 CSV 文件
git status --short | grep -i "\.csv"
```

### 12.2 安全规则

| 规则 | 说明 |
|------|------|
| .local-import-samples/ 必须被 .gitignore 忽略 | 确保该目录不进入 Git |
| 如果 git status 显示 .csv 文件 | **立即停止，不要 commit** |
| 如果 git status 显示 private-import-samples/ 或 local-import-samples/ | **立即停止，检查 .gitignore** |
| 不要用 git add -A 或 git add . 盲目提交 | 始终用 git status 确认 |
| docs/ 和 src/ 下不应该出现真实产品 CSV | 只允许测试示例 CSV 模板 |

### 12.3 如果误提交了 CSV

如果发现真实 CSV 已经提交到本地 Git：
1. 立即通知团队
2. 联系仓库管理员
3. 评估是否需要重置提交和清理 Git 历史

**预防永远优于事后处理。**
